DA-06: zero-damping (D3(0)) data, kernel and official cross-check

M06-L and M06-2X have no BJ parameters upstream (only rs6 = 1.581/1.619,
s8 = 0), so the second D3 data set is the only route to dispersion for the
meta-GGAs - the prerequisite of M2 assertion 4.

qwb-data/dispersion/d3zero.yaml: same reference C6/CN/r4r2 tables as d3bj
(written by the same generator from the same parse, bit-identical) plus the
pairwise vdW radius table (666 pairs; upstream R0_ij is a table lookup, not
a sum of atomic radii) and s6/s8/rs6/rs8/alp for six functionals.
damping/zero.f90: t = (rs*r0/r)^alp, f = 1/(1+6*t), E = -(s6*C6*f6/r^6 +
s8*C8*f8/r^8).

K1 additive extension: zero_damping_parameters + vdw_radii_angstrom,
kind d3zero accepted, DampingModel::Zero implemented and checked against
kind. Rust kernel dispatches on dispersion.damping.

Measured: gen_d3_params --check matches 32946 (BJ) / 33634 (zero) upstream
items exactly; fx04_dispersion_zero reproduces the official ZeroDampingParam
over 40 combinations to 1.302e-6 kcal/mol and 2.755e-10 Ha/Bohr, with the
analytic gradient 1.29e-13 Ha/Bohr from central differences; qwb data
verify 32 passed; a new gate step validates the zero-damping set.

Gotcha recorded in the ledger: the zero-damping oracle is ZeroDampingParam,
not ZDampingParam (load_z_damping is a different family); using the wrong
one looks like 'upstream has no zero-damping table'.
