VF-06: the K10 equivalence suite exists and immediately exposes a tolerance conflict

scripts/check_numerics_equivalence.py reads equivalence_tolerance from
qwb-data/numerics/numerics.yaml (no hard-coded numbers), runs each
(approximate path x reference system) case through the CLI, parses result.json
and prints a difference table. Paths that are not implemented are printed as
'not implemented' with the reason instead of being silently skipped.

Measured: RI-MP2 vs canonical MP2 (H2O/def2-SVP correlation energy) differs by
8.526e-05 Ha, which is 85x the declared ri tolerance of 1e-6 Ha. That number
is exactly the ri_error_hartree recorded by SC-05, and RI-MP2 agrees with
PySCF's RI-MP2 to 1e-9 Ha, so it measures auxiliary-basis incompleteness, not
an implementation error. The two algorithms are not the same mathematical
object, so the single ri tolerance cannot mean both.

Therefore the gate step runs in --report mode (prints the table, does not go
red) and VF-06 stays in_progress until the tolerance is re-scoped into
'implementation equivalence' vs 'auxiliary basis quality' (a criteria change
that must bump the numerics data version). pseudospectral waits for IN-03.

Gotcha recorded: the K2 correlation block uses e2_hartree / e_total_hartree,
not energy_hartree - read the contract before guessing field names.
