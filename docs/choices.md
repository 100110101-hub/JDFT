## 十、闭壳层 Fock 约定：一次被外部参考值抓住的系数错误（2026-10-23）

**症状**：T1 想用 HF/STO-3G H2 的文献值 −1.116759 Ha 把能量判到 < 1 mHa，结果我们给出 −0.442003 Ha，差 0.674756 Ha。

**诊断路径**（要点：先证明积分是对的，再查约定）：
1. 打印 H2/STO-3G 的 S、H、2e 积分，与 Szabo–Ostlund 的表逐项对上：S₀₁=0.6599、H₀₀=−1.1210、H₀₁=−0.9594、(00|00)=0.7746、(00|01)=0.4446、(00|11)=0.5700、(01|01)=0.2976 —— **积分层无错**。
2. 于是差 0.674756 只能是能量表达式。该数恰好等于单占据 MO 的 (cc|cc)，也就是交换能的量级。
3. 根因：`build_fock` 用的是 `F = H + 2J − K`。这个形式只在 **P 是自旋轨道密度**（或分 α/β）时成立；我们的 P 是**自旋求和**的闭壳层密度（P = 2Σcc ᵀ），正确形式是 `F = H + J − ½K`。原式把库仑和交换都多算了一倍。

**为什么之前没被抓住**（诊断器撒谎的第三种形态）：H2/STO-3G 只有一个占据 MO，此时 `Tr(PJ) = Tr(PK) = 4(cc|cc)`，于是 KS 路径上 `½Tr(P(2J−K))` 与 `½Tr(PJ)` **数值相等**，LDA 的 −1.1570 看起来完全正常。只有走纯交换路径（HF）才暴露。所以：一个只在单占据体系上验证过的 SCF，不能证明 Fock 约定正确。

**修法（两条约定显式分叉，不再混用）**：
- `qwb-scf::build_fock`：`F = H + J − ½K`，`E_2e = ½ Σ P_ij (J_ij − ½K_ij)`（闭壳层 HF）。
- `rks_scf`：KS 模式 `F = H + J + v_xc`、2e 项取**纯库仑** `½Tr(PJ)`，交换关联只经 `E_xc/v_xc` 进入；`terms` 为空时切到 HF 模式（`F` 用 `build_fock` 的结果）。

**验证**：`cargo test -p qwb-scf --test s02_rks` 中 `hf_sto3g_h2_matches_the_external_reference` 通过（−1.116759 ± 1 mHa，外部参考）；LDA 值不变（−1.1570005），因为该体系的 KS 能量对这里的系数不敏感——这正好说明**外部参考是必需的**，自洽不能代替正确。

## 十一、DIIS：一个会「静默失效」的加速器（2026-10-23）

症状：接上 DIIS 后，所有体系的迭代步数与关闭 DIIS 时**逐位相同**（31 vs 31、297 vs 297）。

根因：DIIS 的加边系统
```
[ B  −1 ] [c]   [0]
[ −1  0 ] [λ] = [−1]
```
是**对称但不定**的。我用 `qwb_linalg::solve_symmetric`（Cholesky 分解）去解，必定失败；而我把失败写成了「返回 `None`，本步退回普通迭代」——于是加速器一次都没生效，却也没有任何报错。这类 bug 比崩溃更危险：它看起来「实现了、测试也过」。

修法：在 `diis.rs` 内部自己写部分主元高斯消元（`m+1 ≤ 9` 阶，几十行），不动 `qwb-linalg` 的冻结接口（I-00）。修复后的效果：

| 体系 | 普通迭代 | DIIS |
|---|---|---|
| H4 四面体 | 25 步 | **5 步** |
| H4 链 | 43 步 | 13 步 |
| H4 松散丛 | **400 步不收敛** | **6 步** |

教训：加速器类组件必须断言「它真的改变了行为」。只测「结果正确」是不够的——关闭加速器的路径同样正确，而步数完全相同的两个配置就是最响的报警。

另注：全 s 函数的对称体系（H2、正方形 H4、线性等距 H4）初猜即近不动点，两步就收敛，根本测不出加速器好坏；必须有低对称体系才能验证 DIIS。这条也解释了为什么之前 S-02 的 H2 用例「看起来很顺」。

## 十二、网格的 `cutoff` 是尺度而不是边界（2026-10-23，X-03/D-13 待收口）

想给 X-03 补一条「水 Σw 与 4π 差 < 1e-10」的测试时，实测 Σw = 3.66e10，差点当成大 bug。查下来是两条**判据本身写错了**：

1. **原子网格的 Σw 不等于 4π。** 径向权重含 `r²` Jacobian，`Σw ≈ ∫4πr²dr = (4π/3)r_max³`。只有**角向**权重之和才恒等于 4π。project.md 里 X-03 那句话按字面照做会误判。
2. **`cutoff` 不是硬边界。** 径向映射是 `r = a·t²/(1−t²)`，`a = cutoff/8`；`t` 夹在 `1−1e-3`，于是最外节点落在约 **62×cutoff**（cutoff=20 → 1248 bohr）。这是有意的：`a` 只定尺度，节点才会在 `[0, cutoff]` 内保持分辨率。

证据（新增 `qwb-grid/tests/x03_weights.rs`）：网格对解析高斯 `e^{-αr²}` 的积分相对误差 6e-12 / 9e-13 / 4e-12（α = 0.5/1/2），这是网格**能用**的直接证明；而最远点确实是 1248 bohr。远方那几十个节点的权重高达 ~1e9，但那里的密度早已是 0——所以 SCF 一直没被它坑（也顺带说明 S-02 早期「E_xc 偏大 12.6 倍」那类 4π 事故为什么危害更大：那是**全域**的系数错）。

待定：是否换成 Mura–Knowles 一类**有界**映射，让 `cutoff` 名副其实。直接改 `a` 使最外节点 = cutoff 会让全部节点挤到 r < 1，网格反而变差；换映射则会轻微移动所有 SCF 数字（需要重跑 T1 的注册参考值）。所以留到 D-13/X-03 收口时一并对齐，不在已验证的数字上轻举妄动。

## 十三、Boys 函数：差分的自检看不出来的那种错（2026-10-24）

G-01 的解析梯度在 `R = 0.74 Å` 上 2.6e-9 通过、在 `R = 1.1 Å` 上偏 4.6e-3。分项对照（`qwb-scf/tests/g01_components.rs`）把误差锁在**核吸引**一项，而核吸引的两个原始层恒等式（抬阶项、核移动项）对中心差分都是 1e-10 级正确——包括把 `T` 推到 60 以上的远距离点。

问题在 `boys_functions` 本身。旧实现一律用向下递推、顶部固定多算 40 阶。种子 `F_{top+1} = 0` 的误差会被放大 `≈ (2x)^top/(2top−1)!!` 倍，固定 padding 时这个倍数随 `x` 增长得比 `F_top` 衰减更快，于是大 `x` 下 `F_0` **整体**错掉：

| x | 旧实现 `F_0` 相对误差 |
|---|---|
| 12 | 7.6e-11 |
| 16 | 2.9e-8 |
| 20 | 8.1e-6 |
| 26 | 1.8e-3 |
| 33.9 | 8.6e-2 |

STO-3G 氢的最紧指数（3.425）配上 2.078 bohr 的核间距就落在 `x ≈ 30` 那一档，正好是水/氢分子梯度里 1e-3 量级的来源。

**为什么差分自检没抓住它**：抬阶恒等式 `∂/∂A⟨ss|−Z/r_C⟩ = 2α⟨(x−A_x)s|−Z/r_C⟩` 两边用的是同一个错的 `F_0`，而 `T` 只随中心位置变、不随幂次变，所以两边同比例错、差分为零。只有让 `T` 在 ±δ 两侧取到不同值（即比较**跨 T 的 `∂F_0/∂x` 与 `F_1`）才会露出来。这是本次最值得记住的一条：**恒等式检验只能证明内部自洽，不能证明共用的原语是对的**；原语必须另有外部锚点（这里是 `F_0 = ½√(π/x)·erf(√x)` 与 `F_0(1)` 的已知值）。

修法：`x ≥ 30` 改用余误差函数的渐近展开给出 `F_0`，再**向上**递推 `F_{m+1} = ((2m+1)F_m − e^{−x})/(2x)`（大 `x` 下向上是收缩方向）；`x < 30` 保留向下递推，但 padding 改成 `40 + 2⌈x⌉`。两支在 `x = 30` 处的相对差 < 1e-14。测试（`boys.rs` 的 `tests` 模块）在两段区间分别钉住 `F_0 = ½√(π/x)erf(√x)`、递推残差，以及「`x = 60` 的 `F_0` 必须接近其渐近值」——旧的 `large_x_stays_positive_and_small` 断言过 `F_0(60) < 0.05`，而真值是 0.1144，等于把 bug 当成了规格，这次一并改掉。

## 十四、解析梯度里的两个符号错误：抬阶恒等式与核排斥（2026-10-24）

G-01 修完 Boys 后仍差一个整体符号，最终定位到两处**互相掩盖**的符号错：

1. **抬阶恒等式**。设 `u = r − A`，则 `∂u/∂A = −1`，于是
   `∂/∂A_x[u_x^a e^{−αu²}] = −a·u_x^{a−1} + 2α·u_x^{a+1}`。
   代码里写成了 `−2α·(抬阶项)`，符号反了（s 型只有抬阶项，所以永远只差一个负号）。
2. **核排斥导数**。`E_nuc = Z_AZ_B/r`，故 `∂E_nuc/∂R_A = −Z_AZ_B(R_A−R_B)/r³`，代码漏了负号。

两条同时错时，`Tr(P dH)` 与 `dE_nuc` 的一部分相消，总误差看起来只有 0.0111 而不是 1.02，误导了整整一轮排查。教训不是「小心符号」，而是**分项对照必须一项一项地比**：`g01_components.rs` 现在把 `动能 / 核吸引(AO 移动) / 核吸引(核移动) / 2e / Pulay / 核排斥` 六项各自对固定密度的差分断言到 1e-6 以内，任一项写反立刻单点报错，不会再互相抵消。

修完后的验收：`g01_analytic`（H2/STO-3G，R = 0.74 与 1.10 Å）解析与全弛豫数值梯度的最大分量差 3.4e-9 Ha/Bohr。

## 十五、CH2 数值梯度的平移不变性残差：先排除网格，再认账（2026-10-24）

`qwb-engine/tests/g01_numeric_gradient.rs` 里「三原子体系合力应为 0」的那条，实测 z 分量残差 1.0e-4，卡在 1e-4 容差边上失败。第一嫌疑是**网格随几何移动**（见 §十二：网格由分子几何生成，FD 两侧的网格点并不相同），于是直接做了对照实验，用同一分子同一几何换三种网格：

| 网格 | 合力 z 残差 |
|---|---|
| grid-coarse | −1.007e-4 |
| grid-normal | −2.121e-4 |

**残差没有随网格变细而变小，反而变大**，所以「网格噪声」这个解释被证伪——这一点很重要，否则会顺手把容差调大当无事发生。

FD 步长 1e-3 Bohr 下，1e-4 的力残差相当于能量对几何不平滑约 2e-7 Ha，而 SCF 收敛误差是 1e-12。最可能的解释是单重态 CH2 在 ±δ 两侧落到邻近的 SCF 解上（这个体系本身近简并），但**没有验证**，所以不计入结论。该测试已改成 `#[ignore]` 并在属性与 `docs/status.yaml` 的 G-01 里写明实测数字，等有固定网格/固定初猜的 FD 复测再收口。

对照：解析梯度这条路径本身在 H2/STO-3G 上对同一套 FD 是 3.4e-9。所以「数值梯度不可靠」与「解析梯度不对」是两件事，不能互相顶替。

## 十六、重原子的 XC 网格：一个「三 Ha 且不单调」的坏信号（2026-10-24）

S-03 收口时想拿 H₂O/STO-3G/PBE 做正式体系，顺手把四个网格等级都跑了一遍，得到：

| 网格 | PBE | SVWN5 |
|---|---|---|
| grid-coarse | −74.27601950 | −73.67328369 |
| grid-normal | −77.43625901 | −76.74534823 |
| grid-fine | −74.44047360 | −73.98070008 |
| grid-veryfine | −73.65429773 | 未测 |

**三 Ha 量级，而且不单调。** 同一套网格用在 H₂ 上是收敛的（PBE 四个等级 −1.18117152 → −1.18118271，相邻差 1.0e-5、8e-7、1e-9），所以网格代码本身没坏，坏在这一层更上面。第二天把它逼成了诊断，四条测量互相印证：

1. **固定密度的电子数就不对**：`∫ρ dr` 该是 10，四个等级给 10.0955 / 10.8947 / 9.8018 / 9.5883。
2. **径向加密收敛到错值**：99→200→400，`∫ρ` 收敛到 9.8176（200 与 400 逐位相同），说明径向已经收敛，收敛值本身是错的。
3. **角向加密乱跳**：阶数 590→3200，`∫ρ` 走 9.82 / 10.77 / 10.20 / 9.98 / 10.00，`E_xc` 走 −8.65 / −13.06 / −10.41 / −9.41 / −9.55。
4. **Becke 锐度无效**：0.2→1.6，`∫ρ` 只从 9.7944 动到 9.8419。

每一层单独看都是好的：O 中心原子网格对 α 到 300 的高斯准到 4e-14，分子网格对同一批高斯准到 1e-9，`ao_value` 与手写收缩差 1e-16，O 中心原子网格单独积 ρ 正好 10.00000000。**关键的一刀**是「以 H 为中心的原子网格对 O 处的 α=130 高斯差 43%」：每个原子网格只在自己中心附近准确，分子网格全靠分区权重把别人紧核处的贡献压掉，而 Becke 权重在 ν→1 处只是多项式衰减，压不住 ρ ~ 10⁴ 的核尖。

所以这不是「加点数」能修的，要补 X-03 的三件缺项：真 Lebedev 角向表（现在是 `n = ⌈√lebedev_order⌉` 的 Gauss 乘积，阶数语义名不副实）、Becke 的尺寸调整 `ν = μ + a_ij(1−μ²)`、Treutler–Ahlrichs 一类带核心标度的径向映射。

三条要记住的：

1. **不能拿「轻原子收敛」推「重原子收敛」。** H₂ 的 1e-9 曾经让我以为网格这一块已经没问题了；换成水立刻差 3 Ha。等级差测试必须至少含一个重原子。
2. **HF 与 XC 的验证是分开的。** 水的 HF = −74.9629 Ha 与外部参照一致（HF 不经过网格），但同一几何的 PBE/LDA 能量不可引用。所以 I-02 的收口不覆盖这一项。
3. **数字全部留在 `qwb-scf/tests/x03_grid_defect.rs`（`#[ignore]`）与 `docs/error-budget.md` §2**，而不是只写在对话里。修法是换带核心标度的径向映射（Mura–Knowles / Treutler–Ahlrichs），它会移动所有 SCF 数字，必须与 T1 的参考值一起重新标定。

## 十七、角向规则的覆盖：乘积规则为什么乱跳（2026-10-24，X-03 诊断的一部分）

第十六节说角向加密时 `∫ρ` 在 10 附近乱跳。为了分清是「点数不够」还是「点分布不好」，做了一次对照实验：把角向规则临时换成**等面积 Fibonacci 螺旋**（黄金角，点数 = order，权重全等 4π/n），其余一切不动：

| 网格（order） | 乘积规则 ∫ρ | Fibonacci ∫ρ |
|---|---|---|
| grid-coarse（50） | 10.0955 | 9.2244 |
| grid-normal（194） | 10.8947 | 9.5910 |
| grid-fine（590） | 9.8018 | 9.8940 |
| grid-veryfine | 9.5883 | 10.0637 |

乘积规则是乱的（甚至偏离方向都不固定），Fibonacci 是**单调**逼向 10 的。这排除了「角向点数不够是唯一原因」的说法：`n = ⌈√order⌉` 的 Gauss–Legendre × 等距 φ 乘积规则在球面上分布不均——它在两极聚集、在赤道稀疏，而 Becke 分区加权后的被积函数往往集中在某一个帽状区域，正好落在稀疏处。

但 Fibonacci 也只是「更守规矩」，1% 量级的缺口还在（且径向加密后 `∫ρ` 仍收敛到 9.92 而非 10）。所以结论没有变：需要真正的 Lebedev 表（均匀覆盖且对球谐精确到该阶）+ Becke 尺寸调整 + Treutler–Ahlrichs 径向。

实验已回滚——半对的角向规则会移动所有 SCF 数字却仍达不到 §7 容差，不如把缺陷留成显式的 known-defect（`x03_grid_defect.rs`）。


## 十八、Becke 分区写反了一个符号：三条「通过」的测试为什么没抓住（2026-10-24）

上一轮把水那 3 Ha 的 XC 不收敛逼到了「分子网格」这一层，这一轮用**按半径分箱的电子数**定位到了根因：

| 到 O 核的距离 | 分子网格（Becke） | O 中心原子网格（无分区） |
|---|---|---|
| 0–0.001 bohr | 0.00000000 | 0.00000107 |
| 0.001–0.010 | **0.00000000** | 0.00088431 |
| 0.010–0.050 | **0.00000000** | 0.08020939 |
| 0.050–0.100 | **0.00000000** | 0.35537777 |
| 0.100–0.200 | 1.19429981 | 0.85072307 |

分子网格在 O 核周围 0.1 bohr 以内积出**精确的零**，而那里有 0.44 个电子。也就是说：O 自己的网格拿到 ≈0 权重，而被分到权重的 H 网格在那里一个点都没有。

根因是两个字符：`smoothed_step` 返回 `½(1 + p^k(ν))`，Becke 标准式是 `½(1 − p^k(ν))`。**正好是补**。于是「离谁近就归谁」变成了「离谁近就不归谁」。

修好之后：`∫ρ` = 9.99999998，H₂O/SVWN5 四个等级 −74.9282545 / −74.9281445 / −74.9281498 / −74.9281495，相邻差 5e-6 / 3e-7 Ha。

**为什么三条既有测试全都没抓住**：

1. `Σw = 4π`：它只检验角向权重之和，与分区无关（每个点 Σ_i P_i = 1 是归一化保证的，即使 P_i 分错了对象）。
2. 「单原子分区权重恒为 1」：单原子时 `i ≠ j` 的循环不执行，`log_weights` 全 0，分区恒为 1——**恒真**，测不出任何东西。
3. 平滑高斯（α = 0.5/1/2）：核区贡献 ∝ 体积 ∝ r³，α=1 时 0.1 bohr 内的份额是 1e-3 量级，分区反了也淹没在 1e-9 的容差里。而 H₂ 之所以一直没问题，也是因为它没有紧核（H 的 ζ ≈ 1.2）。

**所以判据要换**：任何与求积相关的改动，必须至少有一条**电子数**测试（`∫ρ dr` = 电子数，被核心主导）和一条**紧核**被积函数（α ≥ 100）的测试，外加一条**偏离中心**的紧核测试（例如「以 H 为中心的网格积 O 处的高斯」——这条会直接暴露 43% 的偏差）。三条缺一不可，`s02_grid_convergence.rs` 现在把前两条固化进 gate。

## 十九、2e 递推族：规格说 OS，实现是 MD（2026-10-24，正式记录偏差）

`project.md` 把二电子积分记作「Obara–Saika 为主、Rys 交叉验证」。本实现实际走的是 **McMurchie–Davidson**（Hermite 展开）：`hermite2e.rs` 把 Hermite Coulomb 族写成「R 的多项式 × Boys 指标」再做精确符号求导（`∂R^p = p·R^(p−1)`、`∂F_s = −2ρR·F_{s+1}`），而不是靠记忆里的 OS 递推系数。

两条理由，都是可检验的：

1. **可自证**。MD 路线的每个量都能用初等事实推出来并在代码里注释；OS 的递推表则需要外部对照才能确认没抄错。这个项目已经因为「凭记忆写递推」栽过两次（闭壳层 Fock 系数、Hermite 核吸引的 `(−1)^t`）。
2. **精度已经过判据**。`i03_general_l` 用独立数值路径逐分量对照，s 型逐位相同、p/d 型 ≤ 1e-9；`i03_oracle` 五条不依赖参照路径的约束（闭式、交叉对称、平移、共线、绕轴）全过。Rys 那一半由「闭式导数」这条数值路径替代，同样满足「独立参照」的要求。

**但这与规格不同，所以记录下来**：如果将来需要严格 OS（例如要复用 OS 的 shell-pair 缓存），那是另一条实现路线，不是本文档能追认的。选择记为偏差而不是改规格，因为规格是冻结的契约面，改规格要人类拍板。

顺带：这一轮 def2-SVP 一跑就炸的两个 bug 都在装配层而不是递推层——`contract`（笛卡尔→球谐）用了输入布局的偏移去写输出布局，以及网格上的 `ao_value` 对 `l ≥ 2` 直接报错。修掉之后 H₂O/def2-SVP/PBE 端到端跑通（偶极 1.9542 D，1 与 4 线程逐位相同）。（当时的能量 −76.4496675241 Ha 是 PBE 相关项还用 VWN5 做 LDA 基时算的，2026-11-02 换成 PW92 modified 之后是 −76.2720362190 Ha，见三十一节。）

## 二十、几何优化：先分清楚「优化器不对」和「基组不够」（2026-10-24）

T3/G-02 的判据里有一句「H₂O 键长与实验 0.9572 Å 差 < 0.01 Å」。本轮把 BFGS 写出来跑通后，这句话反而成了最容易误判的一条，所以先把它拆开：

| 模型化学 | O–H | ∠HOH | 对实验（0.9572 / 104.5） |
|---|---|---|---|
| HF/STO-3G（实测） | 0.9893 Å | 100.04° | 差 0.032 Å |
| PBE/def2-SVP（文献量级） | ≈0.97 Å | ≈104.5° | 差 ≈0.015 Å |
| PBE/def2-TZVP（应有） | ≈0.966 Å | ≈104.4° | 差 ≈0.009 Å |

也就是说 **0.01 Å 这条判据需要 def2-TZVP 级别的最小基组**，而 D-05/D-06 的数据还没拿到。用 STO-3G 判它，无论优化器写得多对都会失败；反过来，如果谁为了让这条变绿去改判据或改体系，那才是真的错。

**优化器本身的判据**（与体系无关、可以立刻判）：
- 收敛到驻点：最大力 < 4.5e-4 Ha/Bohr —— H₂ 4 步（2.65e-4）、H₂O 5 步（1.75e-4）；
- 解析 vs 数值梯度在驻点一致：3.05e-7 Ha/Bohr（H₂/STO-3G，s 型基组）；
- 对称性：H₂O 两个 O–H 键长在 1e-3 Å 内相等（C2v 自证）。

## 实现要点（写给下一个改它的人）

1. **笛卡尔 vs 内坐标**。现在实现的是笛卡尔 BFGS。它不差在方向上（平移/转动方向的梯度恒为零，不会污染 Hessian），差在**步数**：键角耦合强的体系（CH₄、NH₃）会多走几步。G-02 原文要冗余内坐标，这一条**未做**，已记在账本里。
2. **梯度来源自动切换**。s 型 + HF 走解析梯度（快、准到 3e-7），否则退数值梯度，并在 `OptResult.used_analytic_gradient` 里报告——H₂O 之所以要 8 分钟，就是因为 l > 0 的解析梯度还没做（每个梯度 18 次 SCF）。
3. **收敛判据用力的最大分量**，不用 RMS。RMS 会被「大部分分量接近零」稀释，而几何优化真正卡住的往往就是最大那一个分量。

## 二十一、解析梯度推广到任意角动量：一个「换了索引忘了换指数」的 bug（2026-10-24）

原来的 `analytic_gradient` 只支持 s 型基组（`l > 0` 显式报 Unsupported），所以 H₂O 只能走数值梯度。推广到任意角动量不需要任何新积分，只要两件事：

1. **抬/降幂恒等式**（`u = r − A`，`∂u/∂A = −1`）：
   `∂/∂A_x[u_x^a u_y^b u_z^c e^{−αu²}] = −a·u_x^{a−1}(…) + 2α·u_x^{a+1}(…)`。
   于是任何积分对中心的导数都只是「同一套原函数换两个幂次」，而 `hermite2e::primitive_component` 本来就吃任意幂次。
2. **球谐 → 直角分量**：球谐 AO 是直角分量的线性组合，先把密度展开（逐壳层 `ρ̃ = Tᵀ P T`），在直角基上求导，最后直接求和——梯度是标量，不用变回去。

「核本身在动」那一项也不用新闭式：`⟨a_A|−Z/r_C|b_B⟩` 只依赖 `A−C`、`B−C`，所以 `∂/∂C = −(∂/∂A + ∂/∂B)`（C 固定）。

**踩到的那个 bug**：2e 的交换积分槽位顺序是 `(ac|bd)`。我把**索引**换了位（`[a, c, b, d]`），却忘了把**指数**一起换位，于是 A 的指数被配到 C 的中心上。症状一度很像「整个 2e 项符号反了」（误差 1.3e-1，但平移不变性仍然成立——因为错误是内部重新分配，不破坏总和为零）。

**定位靠的还是分项**：把六项分别对「固定密度差分」比，动能与核吸引都对到 1e-8，只剩 2e 错，于是范围立刻缩到这个函数的槽位映射上。这是这个项目里第三次由分项对照直接指出 bug（前两次是 G-01 的符号与 Boys）。

修好后：H₂O/STO-3G（含 p）解析 vs 数值 6.7e-7 Ha/Bohr；数值参照自己在 δ=1e-3 与 4e-3 之间的散布是 9.3e-6，所以解析值落在参照的噪声里；平移不变性 1e-15。用解析梯度重跑同一个 H₂O 优化，落到**同一个驻点**（0.9893 Å/100.04°，E 差 1e-10）——这是端到端的独立确认。

## 二十二、两处热路径上的真·性能问题（2026-10-24，行为不变的修复）

跑 G-03 的三个分子被打断，顺手把两处热路径的问题修了。它们都**不改变任何数值**，但把耗时降了一个数量级以上：

1. **纯 HF 也走了一遍网格。** `rks_scf` 每步都调 `evaluate_xc`，即使 `terms` 为空（纯 HF）——那时 `E_xc ≡ 0`、`v_xc ≡ 0` 是精确结果，而求值要按点算 AO 值与密度（H₂O/STO-3G 的 grid-coarse 是 29400 点 × 7 个 AO，每步一次）。跳过之后 H₂O/HF 的 SCF 从 **3.2 秒降到 0.27 秒**，能量逐位不变（−74.96294668 Ha）。
2. **`primitive_component` 每次分配一个 Boys 向量。** 解析梯度的 2e 项是**每个 primitive 四元组**调一次，1 万次量级的分配在 debug 构建里能吃掉一半时间。新增 `boys_functions_into`（栈上缓冲，`top+1 ≤ 320` 时堆上零分配），`hermite2e` 改用它。

第 2 条的写法值得留一笔：向下递推要**从最高阶往下**写，而输出只要前 `m_max+1` 个，所以不能直接写进 `out`；用一个小栈数组 `[f64; 320]` 兜住 `top+1`，最后 `copy_from_slice` 拷回。用堆再释放就没意义了。

顺带记一个真实能力边界：笛卡尔 2e 梯度的复杂度是 `n_cart⁴ × 原函数组合数`，CH₄/STO-3G（`n_cart = 9`）就已经是分钟级。要进 gate 得先上「按壳层分块 + 预筛」或「OS 的 shell-pair 缓存」——那是另一个 WP 的量，不是这里顺手能修的。

## 二十三、Hessian 与简正模：两个「我自己的测试先写错」的地方（2026-10-25）

F-01/F-02 的 Hessian 写出来之后，测试先挂了两次，两次都是**测试的理解**错，不是实现错。记在这里因为它们很容易再犯：

1. **三点拟合曲率与 Hessian 元的因子关系。** 写测试时让两个 H 对称各移动 δ，然后拿 `(E(+δ) − 2E(0) + E(−δ))/δ²` 与 Hessian 的 `H[z0,z0]` 比，差了 4 倍。原因是：只移动**一个**原子时，键长变化量 = 位移量，曲率就等于 `H[z0,z0]`；而两个原子各动 δ 时键长变化 2δ，曲率变成 4 倍。判据必须与被测的自由度精确对应——这个项目里第三次栽在「因子没对齐」上（前两次是闭壳层 Fock 的 2 倍、K 的 1/2）。
2. **ZPE 把平移/转动模算进去了。** H₂ 在驻点算出来是 `[0, 0, 0, 110.5, 110.5, 5476.8]`，ZPE 直接对「所有正波数」求和得 2848.9，而正确值是 5476.8/2 = 2738.4。平移/转动模不是振动，不该进 ZPE。修法是先数清振动模个数（非线性 3N−6、线性 3N−5，本模块用共线判定 `is_linear`），再取**最大的**那几个。

另外两个观察：

* 110.5 cm⁻¹ 那对「转动模」不是 bug，是**残余力**的反映：优化后的最大力是 2.65e-4 Ha/Bohr，对应的曲率污染 ~3e-4 Ha/Bohr²，换算过来正好是一百多波数。要做「纯振动」分析，得先把几何收到更紧（或做投影）。
* H₂/STO-3G 的伸缩模 5477 cm⁻¹ 对实验 4401 高 24%，水三个模 2169/4141/4392 也是同样的偏高。这是 STO-3G + 谐振近似的系统性结果，不是实现错误——所以没有拿它去凑实验值，而是记成「外部参考待核实」。

质量表目前硬编码在 `hessian.rs`（IUPAC 2021 标准原子量）。按项目的数据纪律它该进 `qwb-data/` 并带引用，记为**待迁移的欠账**。

## 二十四、KS 解析梯度缺的那一项：为什么 HF 一直对、换到 PBE 就错 1.4e-1（2026-10-25）

把 `v_xc` 加进 Fock 之后，我以为 KS 的解析梯度只是「接线」——因为 Pulay 项 `W = ½PFP` 用的是完整 Fock，看起来一切都对。实测 H₂/STO-3G/PBE：解析 0.0158541、数值 −0.1262239，差 **1.42e-1**。

原因在于**能量表达式多了一项**。HF 是

```text
E = Tr(PH) + E_2e + E_nuc
dE = Tr(dP·F) + Tr(P dH) + 显式2e + dE_nuc        F = H + G
```

而 KS 是

```text
E = Tr(PH) + E_2e + E_xc(P) + E_nuc
dE = Tr(dP·F_KS) + Tr(P dH) + 显式2e + **显式XC** + dE_nuc
```

其中 `Tr(dP·F_KS) = −Tr(W dS)`（把 `v_xc` 加进 F 就对了），但**显式 XC 项**
`∫ v_xc(r)·(∂ρ/∂R)|_{P 固定} dr` 现在完全没算。它在 HF 里恒为零（因为 `E_xc ≡ 0`），
所以 HF 分支从 G-01 到现在一直是正确的——这个缺口只有把 Fock 换成 KS 之后才会暴露。

补它需要 `evaluate_xc` 再吐一个「势函数级」的量：

```text
V'_{μν}^{(A,x)} = Σ_p w_p · v(r_p) · (∂_A,x φ_μ · φ_ν + φ_μ · ∂_A,x φ_ν)
显式XC = Tr(P · V')
```

即：把网格点上的**势**（不是矩阵）与 AO 导数配对再做一次 3-指标收缩。`ao_value_and_gradient`
已经有 AO 导数，缺的是让 `evaluate_xc` 顺便返回势值。

**这一条记成 known-gap 而不是悄悄修**：测试 `g01_analytic_pbe.rs` 标了 `#[ignore]` 并把
1.42e-1 的实测值写进属性；优化器退回 HF-only 的解析路径（KS 继续走数值梯度）。
`docs/unblock.md` 第四节把它列为「可自推」的第一项，判据就用这条测试。

顺带一条方法论：这次错误**没被任何「内部自洽」测试抓住**，因为优化器只在 HF 分支用解析梯度，
而 g01_analytic/g01_components 全是 HF。同一个公式在两个分支上共享，却只有一个分支被验证——
这类缺口只能靠「把新分支也接上同一条断言」来暴露。


## 二十五、基组不再手抄：从 Basis Set Exchange 生成（2026-10-25）

D-05/D-06 卡了很久，原因是「缺基组文件」——而手抄几百个指数与收缩系数一次抄错就是静默错。这一轮换了做法：`scripts/gen_basis_from_bse.py` 直接从 BSE 的 Python 包生成 K1 格式的 YAML，再由 `qwb-stamp-data` 打 sha256、`qwb data verify` 校验。

**转换器的正确性用已有数据自证**：拿同一个脚本重新生成 `def2-SVP`，与仓库里手抄的 `def2-svp.yaml` 逐数对比 —— 41 个指数的最大差 **0.00e+00**（指数与收缩系数都逐位相同）。这样「生成器可信」不是我说了算。

### 踩到的第一个坑：BSE 的「sp 复合壳层」

第一版生成器对每个 `l` 都写出该壳层的**全部**系数数组。对 def2 系列没问题（每壳层只有一个 `l`），但 6-311G(d,p) 的 O 有 `angular_momentum: [0, 1]` 加**两个**数组的复合壳层：数组 0 归 s、数组 1 归 p。于是 30 个基函数被撑成 42 个，S 矩阵多出 8 个 ~1e-16 的本征值，PBE 优化居然把水跑成**线性**（∠HOH = 180°，键长 0.9681 Å）。

修法：`len(angular_momentum) > 1` 时按位置一一配对。同时给生成器加了**函数数自检**——用 BSE 的 `l` 列表算出期望的 Σ(2l+1)，与实际生成的壳层数比，不等就拒绝写文件。这类错误必须由工具拦，不能靠眼睛。

### 踩到的第二个坑：近线性相关要截断，不是报错

6-311G 系列本身就近线性相关（三重分裂共享同一套指数）。原来的 `S^{-1/2}` 要求重叠矩阵严格正定，遇到 1e-16 的本征值直接 `Err`，于是这个基组「不可用」。改成**秩截断的规范正交化**：丢掉小于 `最大本征值 × 1e-10` 的方向，并把警告**每进程只打一次**（SCF 每次迭代都会调这个函数，逐次打印会把真正的输出淹掉）。这是标准做法（多数程序都这么处理近线性相关基组），但必须显式提示——所以保留 warning 而不是静默。

### 结果

* `def2-TZVP` 的数据已到位并可校验，**但它带 f（l=3）**，而 `qwb_basis::spherical` 只到 d：所以 D-06 记 `in_progress`，卡点从「缺数据」变成了「缺 f 变换」（代码问题）。
* `6-311G(d,p)` 是三 zeta 质量且**无 f**，拿去判 T3 的几何判据。
* `cc-pVDZ` 随时可加（也只有 d），留给 V-03 的参考表一起做。


## 二十六、两个更正：CCCBDB 的 URL 参数靠不住；以及一个把「势能面坏了」误判害了的角度公式（2026-10-25）

### 1. CCCBDB 的 `method=59&basis=20` 并不等于 HF/STO-3G

为了补 V-03 缺的参考能量，我去取了 CCCBDB 的 `energy3x.asp?method=59&basis=20&casno=74828`（甲烷）。返回的页面标题写得很清楚：

```text
using model chemistry: B2PLYP=FULL/STO-3G
```

也就是说 `method=59` 根本不是 HF —— 而账本 I-02 里一直写着「NIST CCCBDB 的 HF/STO-3G 水 = −75.204892，`energy3x.asp?method=59&basis=20`」。那条引用**很可能是 B2PLYP=FULL/STO-3G 的总能量**（相关能把它压到 HF 之下约 0.24 Ha，量级也对得上）。

对结论的影响：**不影响**。I-02 真正的修复依据是「实验几何下 HF/STO-3G = −74.963」与 MO 能级，和那条引用无关。但引用本身必须更正，否则以后有人照着它去核账会得出「我们差 0.24 Ha」的错误结论。

做法：把 I-02 的 note 里那条引用改成「CCCBDB 页面（method/basis 参数无法从 URL 选定；该页返回的是 B2PLYP=FULL/STO-3G，不是 HF/STO-3G）」，并注明 HF 参照另有两处支撑（实验几何的 −74.963 与 MO 能级）。

**教训**：从网页抓参考值，必须核对页面自己声明的 method/basis，不能相信 URL 参数。这个坑账本里其实早记过一句「URL 参数对该页不生效」，但那条引用还是留了下来。

### 2. 角度公式混单位，差点让我误判「PBE 的势能面坏了」

PBE/6-311G(d,p) 优化水时，我的测试把 ∠HOH 算成 **180.00°**（线性），而 HF 路径给的是正确的 100.04°。差一步就要把「KS 的弯曲模式坏了」写进账本。

原因在测试自己：`r1`、`r2` 换成了 Å，而 `r12` 留在 Bohr，余弦恒接近 −1 → 角度恒为 180°。修正（全部在 Bohr 下算余弦）后，优化的确是弯曲的。

顺带做了一次**不依赖优化器**的判据：同一键长下直接比较两个角度的单点能（PBE/6-311G(d,p)）：

| 几何 | grid-coarse | grid-normal |
| --- | --- | --- |
| 弯曲 104.5° | −76.5378434676 | −76.5378915196 |
| 线性 180° | −76.4868697767 | −76.4863790811 |

弯曲比线性低 **0.051 Ha**（32 kcal/mol），与化学常识一致 ⇒ 势能面没问题，问题只在优化器的数值梯度（网格随几何变化带来的噪声，见十六节）。

**教训**：当优化器给出物理上荒谬的结构时，先用**单点能**直接比较两个构型，再决定怪优化器还是怪能量。这一步只要两次 SCF。


## 二十七、f 函数（l = 3）的球谐变换：用构造代替抄系数（2026-10-25）

def2-TZVP 的 O/C/N 带 f 函数，而 `spherical_transform` 原来只到 d，于是 H₂O/def2-TZVP 直接报 `Unsupported`。补 f 变换有两条路：抄一份 10×7 的系数表，或者**构造**出正交归一的基。选了后者：

1. 三次单项式空间（10 维）= `f(7) ⊕ r²·p(3)`；
2. 取七个实立方谐波的多项式形式（`z(5z²−r²)`、`x(5z²−r²)`、`z(x²−y²)`、`xyz`、`x(x²−3y²)` 及其 ±y 对应）；
3. 在**重叠度规** `S`（归一化直角原函数之间的自重叠，见 `f_overlap_metric_value`）下先把它们对 `r²·x, r²·y, r²·z` 做投影，再正交归一。

这样 `TᵀST = I₇` 与「与 `r²·p` 正交」都是构造保证的（实测 2.2e-16 / 1.1e-15），不需要手推每一列的归一化常数——本项目已经因为「凭记忆写系数」栽过两次（闭壳层 Fock、Hermite 核吸引的 `(−1)^t`）。

**过程中发现的一件事**：我一开始以为七个谐波在 `S` 下已经互相正交，只做逐列归一化就够了。实测有两对不正交（偏差 0.68）。原因不是系数写错，而是「同一轴上的 1D 归一化比值之积」与三维归一化之间的换算容易搞混；与其去把这套换算推干净，不如让 Gram–Schmidt 去做——它只用「内积是 S 内积」这一件事。

**验证**（三层，一层比一层接近物理）：
* `TᵀST = I₇`（数学自洽）；
* 七个 f 与 `r²·p` 正交（子空间没错）；
* 端到端：H₂O 的 HF 能量在三个基组上单调收敛（def2-SVP −75.9610 → 6-311G(d,p) −76.0464 → def2-TZVP −76.0590 Ha），而此前 def2-TZVP 连算都算不了。

**范围**：R-06 的第一阶段因此从 s/p/d 扩到 **s/p/d/f**；`l ≥ 4` 仍然显式返回 `None`（系数不猜）。

## 二十五、键长判据的定性：不是基组，是泛函（2026-11-01）

上一轮把基组数据从 BSE 生成出来（def2-TZVP 与 6-311G(d,p) 进了仓库），本以为 T3 那条「H₂O 键长与实验 0.9572 Å 差 < 0.01 Å」就能过。实测把它否掉了：

| 模型化学 | O–H (Å) | 对实验 0.9572 |
|---|---|---|
| HF/STO-3G | 0.9893 | 0.0321 |
| PBE/def2-SVP | 0.9682 | 0.0110 |
| PBE/6-311G(d,p) | 0.9682 | 0.0110 |
| PBE/def2-TZVP | **0.9689** | **0.0117** |

关键在读法：基组从 SVP 换到 TZVP（函数数 24 → 43，加了 f 壳层），键长只**往上**动了 0.0007 Å。三个 PBE 结果挤在 0.9682–0.9689，说明这是 PBE 的**收敛值**，而实验 r_e 是 0.9572——差的 0.011 Å 来自泛函，不是基组，也不是优化器。

（同一轮另一个数也支持这个判断：键角 104.42° 对实验 104.5° 只差 0.08°，几何本身没有系统性问题。）

所以 T3 的收口依赖链被改写了：

```text
D-11 (B88) + D-12 (HF 交换混入)  →  T6 (B3LYP, O–H ≈ 0.963)  →  T3/G-02 的键长判据
```

这条链比原来的「等 D-06 基组」更长，但**方向是确定的**：0.01 Å 的容差对纯 GGA 太紧，对 B3LYP 刚好够（0.963 差 0.006）。

顺带记两个本轮的方法学教训：

1. **判据要写在「模型化学」这一层，不要写在「实现」这一层**。「键长误差 < 0.01 Å」这句话里其实混了两个东西：几何优化的正确性（已由最大力 < 4.5e-4 判掉）和泛函/基组的精度（这一条得随模型化学走）。把它们分开写，才不会在基组上反复试错。
2. **收敛性比单点值更能说明问题**。单看 def2-TZVP 的 0.9689 会以为是基组不够；把三个基组排在一起看「换基组只动了 0.0007」，才立刻知道瓶颈在泛函。这和前面几次的教训是同一个：**把一个量与另一条独立路径（这里是另一个基组）比**。

## 二十六、B88 与「数据签名」：两件顺手做对的事（2026-11-02）

### B88 只用了四十行

B88（Becke 1988）是纯 GGA 闭式，`ε_x = ε_x^LDA − β·ρ^{1/3}·x²/(1+6β·x·asinh x)`，`x = |∇ρ|/ρ^{4/3}`。它**完全复用** PBE 那套对偶数（值 + ∂/∂ρ + ∂/∂σ），所以实现只需要把公式照抄一遍，不需要碰导数——这是当初把 GGA 做成「值 + 两个偏导」的正确回报。

三条判据都过了：σ→0 退化为 Slater（< 1e-14）、增强因子与闭式一致（< 1e-12）、导数对五点四阶差分一致。

其中一个判据**必须带自校准的舍入地板**：`∂ε/∂σ` 在 ρ 大、σ 小时只有 1e-4 量级，而五点差分的舍入误差是 `8·eps·|ε|/h`——实测「相对差」2.25e-8 恰好就是这个地板。如果按死 1e-9 判，会误判成实现错误。判据写成「相对 1e-9 **或** 落在地板以下」才对。

### `qwb data sign`：手抄摘要是个坑

我一直以为数据文件的 `sha256` 是「文件字节的哈希」，于是算出来对不上，一度写进对话说「这些文件过期了」。**错了**：规范化摘要的定义是

```text
sha256( serde_json( YAML 去掉 sha256 键 ) )
```

按这个定义重算，`pbe` 与 `svwn5` 的声明值**逐位正确**。也就是说文件一直是好的，出问题的是我的理解。

顺手把这件事做成工具（`qwb data sign`）而不是继续手抄：

* 摘要里**排除** `sha256` 键 ⇒ 写回摘要不改变摘要 ⇒ **签名幂等**，可以随时重跑；
* 只改 `sha256:` 那一行，不重排 YAML、不改注释。

给 b88 签名时它立刻派上用场：先写文件 → `data sign` 得到 efa0fa7b… → 写进 registry → `data verify` 12/12 通过。

**教训**：「我以为的哈希口径」和「项目实际的哈希口径」不是一回事，尤其是当它涉及「排除某字段的规范化」这种设计时。核对方式是**拿一个已知正确的文件验证自己的工具**，而不是拿自己的实现去质疑数据。

## 二十七、hybrid 的精确交换混入：两个「逐位退化」判据（2026-11-02）

B3LYP（D-12）的骨架是「按比例混入精确交换」，机制本身与 LYP 无关，所以我先用 **PBE0**（75% PBE 交换 + 25% 精确交换 + 100% PBE 相关）把机制钉住。三条判据：

1. **α = 0 必须逐位退化为 PBE**。数据路径（`rks_from_data("pbe")`）与手搭路径（`α=0` + 同一组 terms）的能量 `to_bits()` 相同 —— 混入项恒零时不该动任何一个数。
2. **α = 1 且 DFT 交换权重 = 0 必须逐位退化为 HF**（最强的一条）。HF 走 `build_fock` 的 `H + J − ½K` 分支，hybrid 走 `H + J + v_xc + α(−½K)` 分支，**两条完全不同的代码路径**给出差 **1.4e-14 Ha** 的能量。这一条同时钉住三件事：Fock 里的 `−½K` 系数、能量里的 `−¼Tr(PK)` 系数、以及 `P = 2Σccᵀ` 的自旋求和约定。
3. **中间值要能独立分解**：PBE0/STO-3G 的水收敛到 −75.4221478533 Ha，用返回的密度重算
   `Tr(PH) + ½Tr(PJ) + E_xc + α(−¼Tr(PK)) + E_nuc = −75.4221478515`，差 1.8e-9。交换项为负（−2.2767）单独断言，把符号写反挡掉。

## 一个被我自己否掉的判据

写测试时我顺手加了「hybrid 应打开 HOMO–LUMO 间隙」，这在本领域是常见说法。实测 **PBE 0.2279 Ha、PBE0 0.2123 Ha** —— 反而略小。原因大概是 STO-3G 这种最小基组下轨道能级的含义本来就有限，而精确交换对占据/空轨道的移动不是同向的。

**结论：把定性「经验」当判据是危险的**。它看起来很有道理，但没有一条推导能支持它在这个基组上成立。改成能量分解复算之后，判据既严格又自证。

## 数据侧怎么表达 α

`HfExchange` 写成 functional 的一个**伪组件**：

```yaml
components:
- id: GgaPbeX
  weight: 0.75
- id: GgaPbeC
  weight: 1.0
- id: HfExchange
  weight: 0.25
```

`rks_from_data` 看到 `HfExchange` 就把它累加进 `RksOptions.hf_exchange`，**不建能量密度项**。好处是不用改 K1 schema，而且以后 B3LYP 只是把这四个权重换成 0.8/0.2/0.81/0.19。

## 二十八、∇²ρ 落地，以及 LYP 为什么不能「顺手写完」（2026-11-02）

LYP 需要网格上的 `∇²ρ`，而 `Requirements.laplacian` 这个字段一直有、却没人提供值。本轮把这条打通：

* `ao_laplacian`：`∇²φ = Σ_axis[a(a−1)u^{a−2} − 2α(2a+1)u^a + 4α²u^{a+2}]`（每个轴只改本轴幂次，再求和）。球谐壳层照旧走 `spherical_transform` 的列。
* `evaluate_xc`：`needs_laplacian` 时供给 `∇²ρ = Σ P_μν(∇²φ_μ φ_ν + 2∇φ_μ·∇φ_ν + φ_μ ∇²φ_ν)`，经 `DensityBatch::with_laplacian` 带给泛函。
* 验收（`tests/laplacian_density.rs`）不依赖任何泛函：AO 级对二阶中心差分 STO-3G 1.3e-7 / def2-SVP 8.6e-8，ρ 级 2.8e-7（相对）。

**然后我发现 LYP 不能顺手写完**，原因值得单独记：

LYP 的 ε 依赖 `(ρ, σ, ∇²ρ)`，所以它的变分势是

```text
v = ε + ρ∂ε/∂ρ − ∇·(2ρ∂ε/∂σ ∇ρ) + ∇²(ρ∂ε/∂∇²ρ)
```

前两部分现有接口能表达（`potential_derivatives` 吐 `d_rho`/`d_sigma`，σ 通道用分部积分转成 `+2ρ∂ε/∂σ ∇ρ·∇(φ_μφ_ν)`）。**第三部分不行**——它需要

```text
∫ w·(ρ∂ε/∂∇²ρ)·∇²(φ_μφ_ν)
```

也就是说要：① `potential_derivatives` 再多吐一个 `d_laplacian`；② `evaluate_xc` 里加一条 `∇²(φ_μφ_ν) = ∇²φ_μφ_ν + 2∇φ_μ·∇φ_ν + φ_μ∇²φ_ν` 的矩阵元通道。

**如果我按「只有 ρ 与 σ 两个通道」去写 LYP，能量表达式看起来没问题，但 v_xc 会缺一整项，SCF 会收敛到一个错的密度上**——而且这种错误极难从能量数值上发现（能量对密度是小量敏感的）。所以我把这一条明确记下来，而不是先写一个「能跑」的版本。

有意思的是，第三通道需要的三样东西现在**全都齐了**：`ao_laplacian`、AO 梯度、`DensityBatch.laplacian`。所以下一步只是接口扩成三通道 + 照原式写 ε，风险已经降下来了。

顺带一句方法论：这两轮的模式是「先把**可验证的前置**做完（Laplacian vs 差分），再动公式」。公式可以抄，接口不能猜——猜错的接口不会报错，只会给出错的物理。

## 二十九、LYP 落地：三通道 + 变分自洽是唯一能自证的判据（2026-11-02）

LYP 是第一个依赖 `∇²ρ` 的项，所以要先把接口从两通道扩到三通道：

* `D`（对偶数）加 `d_laplacian`；
* `FunctionalTerm::potential_derivatives_laplacian` 作为**默认方法**（默认置零并转发两通道），只有 LYP 覆盖它——这样其它五个项一行都不用改；
* `ScaledTerm` 三通道用同一权重缩放（漏掉这条，复合泛函的势会错）；
* `evaluate_xc` 加 `ρ∂ε/∂∇²ρ·∇²(φ_μφ_ν)` 的矩阵元，其中 `∇²(φ_μφ_ν) = ∇²φ_μφ_ν + 2∇φ_μ·∇φ_ν + φ_μ∇²φ_ν`。

公式的核对锚点很重要：`Br = C_Fρ^{5/3} − 2t_W + (1/9)(t_W + ½∇²ρ)` 展开后是 `C_Fρ^{5/3} + (7/24)∇²ρ − (17/72)(σ/ρ)`，而 **+7/24 与 −17/72 这两个系数在三个独立来源里以同样的形式出现**。我拿它们对账，而不是凭记忆写 `(1/9)(t_W + ½∇²ρ)`——这个 `½` 和符号写反都能让能量看着「差不多」。

## 真正的判据：变分自洽

三项导数对差分只能证明「导数代码与能量代码一致」，**证明不了能量表达式本身是变分泛函**。所以我加了 `lyp_variational.rs`：

```text
ΔP = s·M（M 取几个对称 AO 外积）
比较 ΔE 与 Tr(v·ΔP)，残差应随 s 线性下降
实测：s=1e-3 → 3.4e-9；1e-4 → 3.4e-11；1e-5 → 3.4e-13   （严格线性）
```

这一条同时钉住三件事：能量表达式、三个导数通道、以及 `evaluate_xc` 里三条矩阵元通道的**一致性**。如果按两通道实现 LYP，残差会是 O(1) 而不是 O(s)——上一轮「不能顺手写完」的判断就是靠它验证的。

## 一个必须记下的失败：B3LYP 的 SCF 发散

四个组件都齐了（0.8 B88 + 0.2 HF + 0.81 LYP + 0.19 VWN5），但 B3LYP 的 SCF 在 grid-coarse 上 **3 步内以 `density laplacian is not finite (NaN)` 中止**。

已排除：LYP 项本身（逐点扫过 29400 个点，非有限 0 个）、变分自洽（线性下降）。剩两个嫌疑：① 网格太粗；② `evaluate_xc` 的 σ/laplacian 通道用**未截断**的 ρ 乘、泛函内部用 `LOW_DENSITY_FLOOR` 截断过的 ρ——LYP 的 ρ 依赖比 PBE 陡得多，把这个不一致放大了。

**没有为了让测试变绿去加 NaN 屏蔽**（那正是这个项目吃过亏的坑）。测试按 known-failure `#[ignore]`，排查记录写在函数文档里；D-11 记 done（B88 + LYP 两项各自都验证通过），D-12/T6 记 in_progress。

## 另一条冻结边界

B3LYP 的 `requires.laplacian = true` 被 **K1 的 phase-1 语义门禁**拒绝（"no meta-GGA"，§2.2）。所以没有 `b3lyp.yaml`——`qwb data verify` 会对它报错。这是**冻结契约**，我没有改动它，只在文档里写清「代码层支持、数据层等 phase-2 放开」。

## 三十、第一次拿到**外部**基准：CCCBDB 把三条 SCF 判据一次问清（2026-11-02）

到这一节之前，本项目所有 SCF 验证都是**内部自洽**的（能量分解、变分自洽、解析梯度对差分）——能证明"算得一致"，证明不了"算对了"。T2/T3/T6 的判据都写着"与外部参考差 < x mHa"，这才是真正的验收。

### 外部参考从哪来

PBE/def2-SVP 的水在能直接抄的表里查不到（上一轮 T2 的记录），但 **NIST CCCBDB（SRD 101, Release 22, 2022-05）** 的 `energy3x.asp?method=<id>&basis=<id>&casno=<id>` 页面给的是「某个模型化学在**它自己优化几何**处的 0K 电子能 + 3 位小数笛卡尔坐标 + 核排斥能」。它是可以引用的（标准参考数据库），而且 URL 稳定、可脚本抓取。

* `scripts/fetch_cccbdb_reference.py`：限速 2s/请求、遇到 429 指数退避；只取 `Cartesians` 后的**第一张表**（后面那张距离矩阵首列也是 `C1`/`O1`，混进来会把核排斥能算成 3 倍）；
* `scripts/gen_cccbdb_reference.py`：自检「用解析出的坐标重算核排斥能 vs CCCBDB 报告值」——错位时差 3 倍以上，一抓就抓到。苯差 ~4e-2 Ha 是 3 位小数舍入的必然结果，但**极小点处总能量一阶平稳**，二阶项只有 ~1e-6 Ha，所以不影响能量判据；
* 产物：`crates/qwb-scf/tests/reference/cccbdb_{energies,geometries}.csv`，逐行带原始 URL。

**为什么先只用 STO-3G**：STO-3G 没有 d 函数，避开了「Gaussian 默认 6d（笛卡尔）/ 本项目数据层 spherical（5d）」这个基组约定差（6-31G\* 上会混进 1–3 mHa）。等 V-03 扩基组时必须先解决这个约定问题。

### 结果：HF 与 LSDA 精确对上，两个 GGA 都还没对上

`cargo test -p qwb-scf --test t06_reference`（grid-normal，CCCBDB 自己的几何）：

| H2O | LSDA(SVWN5)/STO-3G | -74.939070298 | -74.939072 | **+0.002 mHa** |
| H2O | B3LYP/STO-3G | -75.303760113 | -75.322775 | **+19.0 mHa** |

### 已经排除的（都留了证据）

1. **基组/几何/核排斥/积分**：HF 差 2e-7；
2. **Slater 交换 + VWN5 相关**：LSDA 差 3e-6；
3. **GGA 的点值公式**：在 (ρ,σ,ε) 网格上与教科书写法逐点相符（`E_pbe/(E_lda·F_x)` 比值 1.000000，B88 与 `x²/(1+6βx·asinh x)` 写法也逐点相符）；
4. **σ = |∇ρ|²**：`ao_value_and_gradient` 与 `ao_value` 的中心差分一致到 2e-9（这一条单独查过，因为 HF 的解析梯度用的是**积分导数**、完全不看 AO 梯度，所以 AO 梯度整体标错因子时现有测试全绿）；
5. **网格分辨率**：grid-coarse → grid-normal 只挪 5e-5 Ha，不是网格问题；
6. **B88/LYP 一侧**：B3LYP 用 `0.8·GgaB88X` 时 H2 差 0.3 mHa。

### 顺带纠正一个自己造的坑

上一轮我"推导"出 B3LYP 应该写成 `0.08 Slater + 0.72 B88`（以为 `GgaB88X` 返回的是含 LDA 的完整 B88，那么 0.8 就把 LDA 部分多算了）。**用 CCCBDB 的 H2/STO-3G 一测就否掉了**：`0.8 B88` 差 0.3 mHa，`0.08 Slater + 0.72 B88` 差 6.9 mHa。所以在这个项目的 `GgaB88X` 约定下 0.8 是对的，原先的组合不用改。——结论：这种"等价写法"的推理必须落到一个可执行判据上，否则就是自己给自己写 bug。

### 还没解决的：GGA 的偏差随"核的存在"放大

B3LYP 在水上 +19 mHa、在 H2 上 +0.3 mHa；PBE 在水上 -176 mHa、在 H2 上 -29 mHa。两者符号相反，但都随体系变大而放大，嫌疑集中在**近核高密度区**（O 的 1s：ρ 大、σ 大）里 GGA 项的处理。

目前最具体的一条线索：把 `GgaPbeC` 的梯度项 `H(t)` 与"使总能量对上所需的 H"相比，H2 是 0.0586 vs 0.088、H2O 是 0.352 vs 0.52 ——**都偏小约 1.5 倍**。下一步按 PBE 原文（PRL 77, 3865）逐项核对 `t² = σ/(4k_s²ρ²)`、`A = (β/γ)/(e^{−ε_c/γ}−1)` 与 `H` 的定义，并用 H2（2 个基函数）做手算积分对照。

**记账立场**：D-12 / T6 / T2 都保持 `in_progress`——外部判据没达成就不能写 done。已知失败钉在 `t06_reference.rs` 的 `#[ignore]` 测试里，数字写在属性说明里。

### 再往上钉一层：公式本身与 libxc 源码逐行相符

为了把"公式记错"这个可能性彻底排除，我读了 libxc 的源码（原始 URL 见下）：

* `gga_c_pbe.c`：`t = gdmt/(2 φ k_s dens)`、`a = β/(γ(e^{−ε_c/(γφ³)}−1))`、
  `f3 = t² + a t⁴`、`f4 = (β/γ)f3/(1+a f3)`、`h = γφ³ln(1+f4)`，
  并且 LDA 基是 **`XC_LDA_C_PW_MOD`**（我们的 `GgaPbeC` 用的是 **VWN5**，这是唯一与 libxc 不同的地方）；
* `gga_x_pbe.c` + `work_gga_x.c` + `util.h`：`f0 = κ + μs²`、`f = 1 + κ(1 − κ/f0)`，
  以及 `X2S = 1/(2(6π²)^{1/3})`、`sfact = 2`（非极化时 `x = 2^{1/3}|∇ρ|/ρ^{4/3}`）——
  把 `2^{1/3}` 与 `(6π²)^{1/3}` 约掉，正好等于教科书的
  `s = |∇ρ|/(2(3π²)^{1/3}ρ^{4/3})`，与我们代码里的一致。

结论：**PBE 的点值公式（含自旋标度约定）与 libxc 逐行相符**，所以剩下的偏差不在公式写法，
而在"我们把公式接到流水线上的方式"（LDA 基、σ 通道、能量求和三者之一）。
下一步优先试 **PW_MOD 的 LDA 相关基**（唯一已知的公式差异），再对照 H2 的手算积分。

### 一条把可能性逼到极限的推理链

设 E[P] 为「用最终密度矩阵重算的总能量」，E_rep 为 SCF 报告的数值。实测（H2O/STO-3G，grid-normal）：

| 泛函 | E_rep | E[P_final] | 差 |
| --- | --- | --- | --- |
| SVWN5 | -74.939054576 | -74.939054576 | 5.6e-10 |
| PBE | -75.414233041 | -75.414233033 | -7.5e-9 |

也就是说：**报告的能量确实是最终密度的能量**（记账没错、E_xc 的求和没错）。
再加上前几轮已经钉死的事实——

1. 点值 ε(ρ,σ) 与 libxc/文献写法逐点相符（PBE-X、PBE-C、LYP、B88）；
2. 网格权重与 ∫ρ 正确（S-02、X-03），LDA 能量精确对上 CCCBDB（1.7e-6）；
3. 我们算出的 PBE 总能量比 CCCBDB 的 PBE **低 176 mHa**。

而变分原理说：对任何密度 E_PBE[ρ] ≥ E_PBE^min。若我们的泛函真是 PBE，就不可能低于参考的极小值。
于是只剩两种可能：

* (a) 参考值不是同一个泛函（已用 `energy3x.asp` 的 "using model chemistry: PBEPBE/STO-3G"
  页面标题核对过，且 B3LYP/H2 在 0.3 mHa 内——概率低）；
* (b) 我们喂给泛函的 **(ρ,σ) 配对不是同一点上的同一个密度梯度**——点值公式对，
  但"送到公式里的 σ"与"ρ"不匹配（例如 σ 用了另一个密度、或网格点顺序错位）。

(b) 是唯一还能同时解释「LDA 精确、GGA 全部偏、且偏差随体系变大」的形状。
下一步（已写进 `docs/unblock.md`）：把每个网格点的 `(ρ, σ, w, |∇ρ|² 独立复算)` 导出，
用两条独立代码路径核对 σ；以及用一次轨道旋转验证 SCF 停在了真正的驻点。

### 三十一、PBE 的 176 mHa 缺口 = LDA 相关基用错了参数化（2026-11-02）

**结论**：`GgaPbeC` 的 LDA 基必须用 **PW92 modified**（libxc 的 `XC_LDA_C_PW_MOD`），
不能用 SVWN5 的 VWN5。换过来之后：

| 体系 | 换基前 | 换基后 | CCCBDB |
| --- | --- | --- | --- |
| H2/STO-3G PBE | -1.181216207（-29.1 mHa） | **-1.152096975（+2.5e-8 Ha）** | -1.152097 |
| H2O/STO-3G PBE | -75.414346083（-175.8 mHa） | **-75.238538040（-4.0e-6 Ha）** | -75.238534 |

**怎么找到的**：绕了很多弯路，最后是"按电子数做量级估算"定案的——
VWN5 与 PW92 在 r_s≈1 处差约 0.02 Ha/e（手算，两个公式都从原文常数代入）：
H2（2 e⁻）需 +0.029 Ha、H2O（10 e⁻）需 +0.176 Ha；按 0.017 Ha/e 估出来是 +0.034 / +0.17，
符号与量级都对上。

**关键教训（写进流程）**：LSDA 精确对上并不能推出"LDA 两个分量都对"——LSDA 用 VWN5，
PBE 的相关项用 PW92，**同一个项目里两套 LDA 基并存**才是标准做法（libxc 就是这么组织的）。
"LSDA 对 ⇒ VWN5 对 ⇒ PBE 也该用 VWN5"这个推理，是这次绕远路的根源。

**还剩什么**：BLYP（+112 mHa）与 B3LYP（+19 mHa）仍偏，两者都含 LYP。LYP 是唯一需要
`∇²ρ` 的项，而"v_xc 是 E_xc 的精确导数"那条测试此前只覆盖 LSDA 与 PBE，
**没覆盖 laplacian 通道**——下一步就做这个。

### 三十二、B88 也要按**每自旋**的约化梯度写（2026-11-02）

修好 PBE 的 LDA 基之后还有一个谜：BLYP 比 CCCBDB 高 112 mHa、B3LYP 高 19 mHa，而
PBE-X 已经精确对上。答案在 B88 的**自变量**上。libxc `gga_x_b88.c` + `work_gga_x.c` 里：

```
x = gdm / ds^{4/3},  gdm = |∇ρ|/2,  ds = ρ/2      ⇒ x_σ = 2^{1/3}·(|∇ρ|/ρ^{4/3})
f = 1 + (β/X_FACTOR_C)·x_σ²/(1 + 6β·x_σ·asinh x_σ),   X_FACTOR_C = (3/4)(6/π)^{1/3} = 0.9305257
```

也就是 B88 的原始形式用的是**每个自旋**的约化梯度、系数里是 X_FACTOR_C（不是 C_x），
而我们原来用的是总密度的 x 与 C_x —— 两项误差方向相反，净效果是梯度修正**弱 21%**。
改对之后（并且注意到 `ε = −C_xρ^{1/3}[1 + …]` 展开时修正项还要乘回 C_x）：

| 体系 | BLYP 改前 | BLYP 改后 | B3LYP 改前 | B3LYP 改后 |
| --- | --- | --- | --- | --- |
| H2/STO-3G | +9.5 mHa | **-0.0001 mHa** | +0.3 mHa | **-0.0004 mHa** |
| H2O/STO-3G | +112.0 mHa | **-0.0001 mHa** | +19.0 mHa | **+0.002 mHa** |
| CO/STO-3G | — | **+0.004 mHa** | — | **+0.003 mHa** |

顺带把 B3LYP 的组合还原成文献写法 `0.08 Slater + 0.72 B88 + 0.81 LYP + 0.19 VWN5`
（B88 修对之前，`0.8 B88` 反而是更接近的组合——那是两个错误互相抵消，不是正确）。

**教训**：同一家族的泛函可能对"约化梯度用总密度还是每自旋"有不同约定（PBE 用 s_total、
B88 用 x_σ），照抄教科书公式时要连着自旋约定一起核。

### 三十四、IR 强度：对称性判据通过，量级判据未通过（2026-11-03）

F-02 的第二半（IR 强度）落地为 `dipole_derivatives` + `ir_intensities`：
中心差分求 `∂μ/∂x`（每次位移一次 SCF，D/Bohr），再投影到简正模
`dμ/dQ_k = Σ_j (∂μ/∂x_j)·(L_kj/√m_j)`，`A = 42.2561·|dμ/dQ|²` km/mol
（`D/(Å·√amu)` 单位下的标准因子）。

**通过**（这是一条不依赖外部数据的强判据）：H2 是同核双原子，伸缩不改变偶极，
六个模的强度实测 **[0, 0, 0, 0, 0, 3.4e-24] km/mol** —— 差分、投影、单位链路的对称性是对的。

**未通过**：H2O/STO-3G（HF）的三个振动模

| 模 | 波数 (cm⁻¹) | 我们 (km/mol) | 文献 ≈ |
| --- | --- | --- | --- |
| 弯曲 | 2169.4 | 7.25 | 67 |
| 对称伸缩 | 4140.8 | 44.26 | 9 |
| 反对称伸缩 | 4392.0 | 29.94 | 52 |

量级落在几~几十 km/mol，但**模式归属与相对大小都不对**（弯曲小了约 9 倍、对称伸缩反而最大）。

已排除的：映射本身不是"本征向量没归一"——`qwb_linalg::symmetric_eigen` 走
`nalgebra::linalg::SymmetricEigen`，其特征向量是正交归一的，而 `displacement = v/√m`
满足 `Σ m·d² = 1`。

剩下的两个嫌疑（下一步二选一验证）：
1. **位移 SCF 的偶极精度**：`HESSIAN_DELTA_BOHR = 0.01` 对偶极来说可能偏大（偶极是平滑量，
   但 SCF 收敛阈值 1e-8 Ha 对应的偶极噪声可能到 1e-3 D，除以 0.02 bohr 就是 0.05 D/bohr
   的噪声；弯曲模的 dμ/dQ 本身就只有 ~0.4 D/(Å√amu)）；
2. **简正模与偶极导数的坐标次序**：`NormalMode::displacement` 的下标是 `[atom][axis]`，
   而 `dipole_derivatives` 返回的是 `[3*atom+axis]`，两者在投影里按下标对齐——
   一旦某个环节用了 `[axis][atom]` 就会整体错位（这种错位对 H2 仍给出 0，所以 H2 判据抓不到）。

H2O 的这条强度测试按 known-failure `#[ignore]` 保留，实测数字写在属性说明里。

### 三十四之补：偶极导数矩阵的输出与"为什么 STO-3G 上不该比强度"

把水/STO-3G 的偶极导数矩阵打出来看（D/Bohr）：

```
原子0(O) 轴x: [-1.4229, 0, 0]      轴y: [0, -0.0794, 0]     轴z: [0, 0, +0.2120]
原子1(H) 轴x: [+0.7114, 0, 0]      轴y: [0, +0.0397, -0.3992] 轴z: [0, -0.5633, -0.1060]
原子2(H) 轴x: [+0.7114, 0, 0]      轴y: [0, +0.0397, +0.3992] 轴z: [0, +0.5633, -0.1060]
```

两条自检都成立：**平移不变性**（三行按原子求和 = 0，逐分量）；**对称性**（两个 H 的镜像关系）。

但**y 分量的量级明显偏小**（H 沿 y 移动 1 Bohr 只让 μ_y 变 0.04 D；弯曲运动主要就在 y 方向）。
结合 2169 cm⁻¹ 的弯曲频率（实验 1595，STO-3G 高 36%）可以判断：**HF/STO-3G 这套模型化学
的势能面与偶极面对水都太差**，不能拿它去比文献强度。

所以结论改成两条：
* 强度机制的**正确性**用对称性判据（H2 全零）钉住；
* 强度的**量**要换更好的模型化学（PBE0/def2-SVP）再比，并且只比"三个模都红外活性"与
  "弯曲 > 对称伸缩"这类稳健关系，不比具体数字。

### 三十五、T4 的"峰位差 < 30 cm⁻¹"到底是什么口径，以及为什么它把自己拖成了慢测试（2026-11-03）

**口径**：未标度的谐和频率对水普遍比实验基频高 3–6%（HF 更高，约 8–10%）。文献里
"频率与实验差 < 30 cm⁻¹"从来都是**乘一个已发表的标度因子**之后再比。所以 T4 的这条判据
我按下面的口径实现，并在这里明写，等人类确认：

* 模型化学：**HF/6-311G(d,p)**（本项目数据名 `6-311g(d,p)`）——选它是因为它是**唯一有完整
  解析梯度**的路线（KS 的解析梯度还缺 v_xc 的基组移动项，见二十四节）；
* 标度因子：**0.909**，来自 NIST CCCBDB Release 22 的
  [Scale factors 表](https://cccbdb.nist.gov/vibscalejustx.asp) 里 HF / 6-311G\*\* 一列；
* 判据：标度后的三个基频与实验（弯曲 1595、对称伸缩 3657、反对称伸缩 3756 cm⁻¹）差 < 30 cm⁻¹。

**为什么没跑出结果（性能发现）**：`f02_frequencies` 在 release 下跑满 39 分钟 CPU、随后 CPU
不再前进（进程卡住）。查了 `qwb-scf/src/analytic_gradient.rs` 的 `gradient_components`：

```text
for atom in 0..natoms {
    for axis in 0..3 {
        ... 一次完整的 O(n_cart^4) 双电子导数求和 ...
```

也就是说 **2e 导数项被按 3N 个坐标各算了一遍**，代价是 3N 倍（水是 9 倍）。
数值 Hessian 又要 18 次这样的梯度 ⇒ 162 次 O(n⁴) 求和。这才是慢的真因，不是网格也不是 SCF。

**下一步（明确）**：把 2e 导数改成**一次遍历 quartet、把 ∂/∂A、∂/∂B、∂/∂C、∂/∂D 分别累加到
四个原子**（标准做法），这样 2e 导数只做一次而不做 3N 次；顺带可加 Schwarz 预筛。
做完之后 T3/T4 的所有慢测试都会从小时级降到分钟级。

### 三十五之补：2e 导数重构之后仍然跑不动 6-311G(d,p) 的 Hessian（2026-11-03 实测）

先把 `gradient_components` 里 2e 导数从"每个原子-轴各扫一遍 n⁴"改成**一次遍历 quartet、
把四个中心分别累加**，并把原函数归一化预算一次（`g01_analytic` 3.2 s、`g01_analytic_water`
57.7 s 均通过，clippy 干净）。但随后实测 HF/6-311G(d,p) 的水 Hessian：

* **6003 秒（100 分钟）仍未跑完**（在 `dipole_derivatives` 之前就超时）；
* 根因不再是 3N 冗余，而是**内层绝对值**：31 个笛卡尔基函数 ⇒ n⁴ = 92 万个 quartet，
  每个再乘原函数组合（6⁴ = 1296）⇒ 每次梯度 ~1e9 次 Hermite 导数求值，
  Hessian 要 18 次这样的梯度。

所以"用 HF/6-311G(d,p) 验 T4 频率"在本环境里不现实。退一步的实测（**STO-3G**，
158 秒跑完）给出数字，但明显达不到 30 cm⁻¹：

| 模 | 谐和 (cm⁻¹) | ×0.909 | 实验 | 差 | 强度 (km/mol) |
| --- | --- | --- | --- | --- | --- |
| 弯曲 | 2169.4 | 1972.0 | 1595 | **+377** | 7.25 |
| 对称伸缩 | 4140.8 | 3764.0 | 3657 | +107 | 44.26 |
| 反对称伸缩 | 4392.0 | 3992.3 | 3756 | +236 | 29.94 |

**结论**：T4 的频率判据要过 30 cm⁻¹，必须先做**双电子导数的预筛/收缩层优化**
（Schwarz 界 + 壳层对预筛，或按壳层而不是按笛卡尔函数做收缩层求和），
让单次梯度从 ~1e9 次原函数求值降到 1e7 量级。这条与 `docs/unblock.md` 里
"2e 梯度分块/预筛"是同一件事，现在有了实测依据（100 分钟 vs 158 秒的两个数据点）。

### 三十六、N2/HF/STO-3G 差 0.684 Ha —— 一个尚未定位的真实不符（2026-11-03）

把外部基准集从 4 个体系扩到 7 个（加 CH4/NH3/N2）之后，六个体系对得很好：

| 体系 | 五个模型化学与 CCCBDB 的最差偏差 |

| H2 / H2O / CO | ≤ 4e-6 Ha（CO 的 BLYP/B3LYP 3.7e-6 / 2.7e-6） |
| CH4 | ≤ 3.2e-6 Ha |
| NH3 | ≤ 1.1e-4 Ha（LSDA/PBE/BLYP/B3LYP 都在 0.09–0.10 mHa，比别的体系大一个量级，已记录） |

N2 的 0.684 Ha 不是数值噪声。已排除：

  （不是共线奇异项的问题）；
* **N 的基组**：NH3 里就有 N，三个模型化学都对到 1e-4 以内。

剩下的线索：占据轨道能级是

**在此之前 N2 不进入 CI 判据**（测试注释里写明"待查、不冒充通过"），参考数据保留。

## 三十七、Windows 的 `os.replace` 不是"原子写"就完事：读者也会被拒（2026-10-25）

P-03 的 `kill -9` 测试在**全量测试 + 门禁同时跑机器**时失败过两次，单独跑却总是绿的。
先怀疑"机器慢"，但把 12 个 CPU 占用进程拉满再跑，测试依然 100% 通过 —— 所以不是慢，
是并发访问。

根因不是调度逻辑，是**平台语义**：

* `os.replace` 在 POSIX 上是原子的 `rename`，永远成功；
* 在 Windows 上是 `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)`，当目标文件**正被别的进程
  打开**（Python 的 `open()` / `Path.read_text()` 不带 `FILE_SHARE_DELETE`）时，
  抛 `PermissionError`(ERROR_SHARING_VIOLATION)；
* 反过来也成立：写方正在 replace 时，读者的 `open()` 同样可能被拒。

而 `queue.json` 的语义恰恰是"多进程同时看"：调度器不断原子替换，测试 / GUI 每 10 ms 读一次。
于是：子进程在 `save()` 时抛 `PermissionError` → CLI 退出 → 队列永远停在 `queued` →
测试的"等到 running+queued"逻辑白等 120 秒（表面症状是超时，真凶在别处）。

修法（`qwb_studio/_fs.py`）：

| 方向 | 函数 | 做法 |
| --- | --- | --- |
| 写 | `atomic_replace(tmp, target)` | `os.replace` 遇 `PermissionError` 就退避重试（≈2.4 s 预算），POSIX 上就是一次 rename |
| 读 | `read_text_retry(path)` | 读被原子替换的文件时同样退避重试；`FileNotFoundError` 照旧上抛 |

用到的位置：`TaskQueue.save/load`、`write_env_json/read_env_json`、`QwbContainer.write_files`。

回归钉在 `qwb-studio/tests/test_atomic_write.py`（3 例）：

1. 把 `os.replace` 前 3 次换成抛 `PermissionError`，第 4 次成功 → 断言重试确实发生且目标内容正确；
2. 永远抛 → 必须在重试预算耗尽后**大声失败**，不许静默丢写；
3. 真并发：一个线程每 2 ms 读一次 `queue.json`，另一个线程连续 `save()` 60 次 →
   两边都不许抛，最终文件仍是合法 JSON。

**教训**：跨平台项目里"原子写"的判据不只是"内容不撕裂"，还包括"并发读者不会被拒"。
Windows 上后者要单独写，而且只有并发用例能测出来 —— 单线程跑一万次也绿。

**另一个教训（关于工具，不是关于代码）**：用 PowerShell 的 `Add-Content` 追加中文内容后，
在 GBK 控制台上看到的乱码是**显示**问题，不是文件问题 —— 判断编码要看"按 UTF-8 解码是否成功
且不含 U+FFFD"，不要看终端长什么样。我曾据此把一段本来正确的记录删了重写。

## 三十八、KS 解析梯度差 1.4e-1：不是一个缺口，是**两个**（2026-10-25）

G-01 挂了几轮，一直记着"缺 `∫v_xc ∂ρ/∂R|_P`"。这次把零件拆开、逐个与有限差分对照之后，
发现是两件事叠在一起，而且第二件比第一件更隐蔽。

### 零件先各自对差分

| 零件 | 对照 | 结果 |
| --- | --- | --- |
| `ao_hessian`（AO 二阶导） | 与 `ao_value_and_gradient` 的中心差分 | 2.4e-10 |
| `ao_laplacian_derivative`（`∂_a∇²φ`） | 与 `ao_laplacian` 的中心差分 | 7.1e-10 |
| `xc_gradient_terms`（PBE） | 与"位移几何重算网格、密度固定"的能量差分 | 8.1e-7 |
| `xc_gradient_terms`（B3LYP 组合） | 同上 | 2.5e-7 |

零件全对，拼起来却还差 8.8e-2。于是把整条梯度按四种拼法摆出来（H2/STO-3G/SVWN5，z 分量）：

| 拼法 | 值 |
| --- | --- |
| 数值梯度（参照） | −0.127181 |
| `F=H+J−½K`，无 XC 显式项 | −0.162753 |
| `F=H+J−½K+v_xc`，无 XC 显式项 | +0.011626 |
| `F=H+J−½K+v_xc`，加 XC 显式项 | −0.215505 |

四种拼法没有一个对。真凶不在 XC：**`gradient_components` 的 2e 骨架项和 Pulay 用的 F
都是按 HF 写死的**（库仑 + 交换、`F = H + J − ½K`）。纯泛函（SVWN5/PBE）根本没有 HF 交换，
把 `−½K` 塞进 KS 的 F 里凭空多出一项，2e 骨架项里也多了一份交换。差 8.8e-2 就是这么来的。

修法：把 2e 骨架项拆成**库仑 / 交换**两半（`two_electron_coulomb` / `two_electron_exchange`），
`F_KS = H + J − ½α_hf K + v_xc`，交换项乘 `α_hf`；并且**由 `rks_analytic_gradient` 自己搭 Fock**，
不给调用方"忘了把 v_xc 加进去 / 忘了 α_hf"的机会。

修完实测（H2/STO-3G）：

| 泛函 | 解析 vs 数值 | 判据 |
| --- | --- | --- |
| LSDA（SVWN5，无 σ 通道） | **1.24e-6** | < 5e-6 ✓ |
| PBE（σ 通道） | **8.40e-7** | < 5e-6 ✓ |
| B3LYP（σ + `∇²ρ` 通道 + α_hf=0.20） | **7.29e-8** | < 1e-6 ✓ |

### 顺带承认一个没算的项：网格权重导数

博恩指数：解析梯度里"网格点/权重随原子移动"那一项**没有算**（主流代码的通行做法）。
这里不靠"通常很小"说服人，而是按网格等级把残留量测出来（H2/STO-3G/B3LYP，δ=1e-3 Bohr）：

| 网格 | 解析 vs 数值 |
| --- | --- |
| coarse | 2.26e-6 |
| normal | **7.29e-8** |
| fine | 2.64e-8 |
| veryfine | 2.25e-8 |

残留随网格变细而收敛 —— 这正是"权重导数项"的特征（公式漏项不会随网格收敛）。
所以 T6 判据 3 用 `grid-normal`（输入文件的默认值）判定，coarse 的数字留在慢档测试里。

### 附带的性能收益

Hessian 原来对每个位移调用**数值**梯度（`3N×2` 次 SCF）。把 `analytic_gradient_flat`
接上 `rks_analytic_gradient` 之后，每个位移只要 1 次 SCF —— 也就是 `3N` 倍。
这是 T4（频率）之前过不去的真正原因之一，不是"2e 导数天生太贵"。

## 三十九、2e 解析梯度快 70 倍：交换项换标号 + 8 重置换对称（2026-10-25）

T4 的频率判据卡在"跑不动"：HF/6-311G(d,p) 的水 Hessian 是 18 个位移 × 2 = 36 次
「SCF + 解析梯度」，而单次解析梯度在 31 个笛卡尔基函数上要 5 分钟量级 —— release 下
跑了 3 小时、CPU 时间 16903 s 还没结束。这不是数值问题，是 `two_electron_all` 的算法问题。

### 两处浪费，都是乘数级的

**① 交换项其实用的是同一张积分。** 原来的循环对每个 quartet 分别算
`d(ab|cd)` 和 `d(ac|bd)` 两套导数积分。但

```text
Σ_{abcd} P_ab P_cd (ac|bd)  ==  Σ_{abcd} P_ac P_bd (ab|cd)      （令 b↔c 换标号）
```

于是 2e 导数可以写成**一张积分、两个权重**：

```text
dE_2e/dR = Σ_{quartets} [ ½ P_ab P_cd − ¼ P_ac P_bd ] · d(ab|cd)/dR
```

导数积分次数立刻减半，而且代码也短了（不再有 `exchange_owners` / `exchange_exponents` 那一套）。

**② 积分有 8 重置换对称，但循环按 n⁴ 全量走。** `(ab|cd)` 在「对内互换」（a↔b、c↔d）
与「换对」（(ab)↔(cd)）下不变。所以只遍历**规范** quartet（`a≤b`、`c≤d`、`(a,b)≤(c,d)`），
每个规范 quartet 只算一次 12 个槽位导数（4 槽 × 3 轴），再把权重按 8 个置换乘回去。

两条合起来：导数积分次数从 `24·n⁴` 降到 `12·(n⁴/8)` ≈ **1/16**，实测 **>70 倍**加速
（16903 s CPU → 155.6 s 跑完整个 Hessian）。

### 写这个优化时踩的坑（值得记）

1. **槽位映射不能"按轨道下标相等去找"**。规范 quartet 里索引会重复（例如 `a==b`），
   此时"成员的第 k 个轨道"不能靠 `position(|index| index == member[k])` 映射回规范槽位 ——
   索引相同但槽位不同，导数是**不同的量**（分别对该轨道所在中心求导）。
   必须用置换映射本身：`member[k] = canonical[perm[k]]`。
   症状很典型：H2 的 z 分量差 1.25e-1，而 x/y 分量为 0（对称性掩盖了一半错误）。
2. **成员的权重必须逐成员算**。库仑权重 `½P_ab P_cd` 在轨内置换下不变，但交换权重
   `−¼P_ac P_bd` **不是**不变的（a↔b 会把它换成 `P_bc P_ad`）。所以不能"算一次权重乘 8"，
   要按去重后的成员逐个算权重，再用该成员的置换把槽位导数映射过去。

### 验收没变

加速不能改变数字，所以原有判据全部重跑：`g01_analytic`（H2，3.4e-9）、
`g01_components`（逐项对固定密度差分）、`gga_xc_gradient`（4 例）、`g01_analytic_water`
（6.7e-7）、`g01_analytic_pbe`（LSDA 1.24e-6 / PBE 8.40e-7）、`t6_b3lyp_gradient`（7.29e-8）
—— 全部继续成立。这也是敢动这块代码的原因：判据足够密、足够严，写错会立刻红。

## 四十、KS 梯度的第三个缺口：网格自己也在动（2026-10-26）

### 怎么发现的

T8 要把 `JobType::Opt` 接到 `EngineBackend` 上，判据点名 **PBE/def2-SVP/opt**。接完先跑了一次
H2O/PBE/def2-SVP/opt，得到 O–H **0.9745 Å**、∠HOH **102.08°**、E = −76.2725558279 Ha（5 步，
最大力 1.42e-4）。数字本身不"炸"，但和 T3 记的 PBE/def2-SVP 的 0.9682 Å 对不上。

于是问了一个更基本的问题：**"解析梯度对不对"这件事，到底在哪些体系上验过？**

答案很难看：`g01_analytic`、`g01_analytic_water`、`g01_analytic_pbe`、`t6_b3lyp_gradient`
**全是 STO-3G**。H2 只有 s 函数，H2O/STO-3G 只有 s/p。而判据点名的是 def2-SVP（O 上有 d）；
更糟的是，**除了 H2 以外，没有任何一个体系验过 KS 梯度在对称破缺几何上的表现**。

### 四象限定位

新写了两条慢档测试（`g01_gradient_localize.rs`、`g01_analytic_def2svp.rs`），把"是不是 d 壳层"
和"是不是 XC 的网格项"分开：

| | s/p 基组（STO-3G） | d 基组（def2-SVP） |
| --- | --- | --- |
| **HF**（无 XC） | 6.7e-7 ✓（旧测试） | **1.138e-7** ✓ |
| **PBE**（有 XC 网格） | **3.304e-4** ✗ | **2.282e-4** ✗ |

结论很干脆：**跟 d 壳层没关系**（HF 在 def2-SVP 上就是 1e-7），是 **XC 的几何导数**。

### 缺的到底是哪一项

`xc_gradient_terms` 算的是"**密度**随原子移动"：

```text
Σ_g w_g [ (ε + ρ ε_ρ)·∂ρ/∂R + (ρ ε_σ)·∂σ/∂R + (∇²ρ 通道) ]
```

但有限网格上的 XC 能量是 `E_xc = Σ_g w_g(R) ε(r_g(R))` —— **网格点和权重也随原子动**：

```text
dE_xc/dR = Σ_g [ (∂w_g/∂R) ε_g + w_g (∂ε_g/∂r)·(∂r_g/∂R) + w_g ∂ε_g/∂(ρ,∇ρ)·∂(ρ,∇ρ)/∂R ]
```

第三项是 `xc_gradient_terms` 算的；**前两项没算**。前两项在 H2 上被镜像对称抹掉（所以
`g01_analytic_pbe` 一直是 8.4e-7），在 H2O 上是 3.3e-4 —— 足以把平衡几何带偏 0.006 Å / 2°。

旧文档里我写的是"网格权重导数是通行做法省略的，通常 1e-6 量级或更小"。**这句话是错的**，
错在拿 H2 的结果外推到所有体系。已在 `xc_gradient_terms` 的文档里改正并写明实测值。

### 修法：固定密度的 XC 几何差分

两条路：

1. **解析**地算 Becke 权重导数（`∂w_g/∂R_A` 涉及所有原子对距离比的切换函数导数，O(N²)/点）；
2. 在**固定密度**下对 `E_xc(R)` 做中心差分：

```text
∂E_xc[P]/∂R_A,x = ( E_xc[P](R + δe) − E_xc[P](R − δe) ) / (2δ)
```

选 2，理由是量级：每算一次梯度多 `6N` 次 **XC 求值**（不用重跑 SCF），水分子上约 1.2 s/次，
一次梯度 ≈ 20 s；而解析权重导数要写 O(N²) 的切换函数导数并重新验证，收益只是省掉这 20 s。
**它是精确包含两项的**（AO 随核动 + 网格随核动），所以是**替代** `xc_gradient_terms`，
不是叠加 —— 叠加就把第三项算两遍了。

代价与边界都写清楚：

* 入口是 `qwb_scf::rks::rks_analytic_gradient_with_xc(.., xc_gradient)`；
  `xc_gradient_terms` 保留（它仍是"部分解析"那一半，单独有测试）；
* 生产路径（`opt`、Hessian）只走 `rks_analytic_gradient_with_xc` +
  `qwb_engine::gradient::xc_geometric_derivative`；
* **还没做**：Becke 权重导数的解析版本。现在的 XC 几何导数是 `O(δ²)` 的差分（δ = 1e-3 Bohr），
  实测与全数值梯度的总差 1.5e-7 Ha/Bohr（下面），比"差分误差"还小，够用。

### 修好之后的实测

| 体系 | 修之前 | 修之后 |
| --- | --- | --- |
| H2O/STO-3G/PBE（最大分量差） | 3.304e-4 | **1.480e-7** |
| H2O/def2-SVP/PBE | 2.282e-4 | **1.589e-7** |
| H2O/def2-SVP/HF（对照，本来就没问题） | 1.138e-7 | 1.138e-7 |

判据是 < 5e-6（与 `g01_analytic_pbe` 同一量级）。这两条测试是 `#[ignore]` 的慢档

### 顺手记下的两件事（不是这次要修的）

1. **T3 的数字是 grid-coarse 的，T8 这次是 grid-normal 的。** 两个网格等级的 PBE/def2-SVP

   vs 0.9745（T8，normal）"不是矛盾，是**网格敏感度**。为确认这一点，直接算了两个几何的单点：
   我们优化出的几何（0.9745 Å / 102.04°）比文献几何（0.9685 Å / 104.4°）**低 3.8e-5 Ha**
   —— 在**我们这条 PBE/def2-SVP/grid-normal 面**上，优化器找到的确实是极小点

2. **H2O/def2-SVP/PBE 在 grid-fine 上 SCF 不收敛**（128 步与 400 步都不收敛，grid-normal 正常）。

## 四十一、把 `opt` 接进引擎时的五个决定（2026-10-26）

T8 要"GUI 里选 PBE/def2-SVP/opt 就能跑"，而 `opt` 在此之前只是一个库函数
（`qwb_engine::opt::optimize`，T3 用过、测试调过），**没有**接到 K2 的 `EngineBackend` 上。
接线时碰到五处"契约没给答案"的地方，逐个决定如下。

### ① 优化后的几何放在哪（K2 没有这个字段）

K2 的 `JobResult` 只有能量/梯度/Hessian/偶极/轨道/日志，**没有几何**；K2 是冻结契约，
`qwb-io` 的 `k3_schema_docs` 与 K6 的 `.pyi` 都跟着它走，加字段要三方一起动。

决定：几何走**旁路**。引擎通过 `OptSink`（`Arc<Mutex<Option<OptReport>>>`）把
`OptReport`（几何/轨迹/步数/是否解析梯度/退化原因）交给调用方，`qwb-cli` 写进
`<task>/artifacts/optimized.xyz`（标准 XYZ，Å）与 `artifacts/optimization.json`。
依据是 K3 自己写的"`artifacts/**` 是自由形态"。

为什么用 `Arc<Mutex>` 而不是 `&mut`：`EngineBackend::run` 是 `&self`（K2 冻结），
而 `Engine::with_backend` 会把后端装箱搬走，调用方拿不回 `&mut`。槽只放一次，读完即空。

副作用（好的那种）：GUI 的 3D 面板因此能画**优化后**的分子，而不是 `input.yaml` 里的初值。

### ② 优化没收敛怎么报

K2 的 `EngineError` 没有"优化未收敛"变体。加一个变体看起来合理（契约文档说变体只允许新增），
但会牵连两处冻结面：K5 的退出码表（`error.rs` 的 `exit_code` 表）与 K6 的
`.pyi` 异常层次（`qwb_engine.ScfNotConvergedError` 这类名字是桩里写死的）。

决定：**不加变体**，复用 `ScfNotConverged { iters, max }`，语义按 K5 的"2 = 收敛失败"读，
`iters/max` 就是优化步数/上限。代价是错误文案仍然是 K2 的 "scf not converged"，
CLI 在 stderr 里另有一段人话（`qwb: ... force threshold ...`）。等哪天 K2 真要加变体，
这里换成 `OptNotConverged` 即可，调用方只看退出码 2。

### ③ `method_name = "hf"` 怎么办

K2 规定 HF 用 `method_name = "hf"`，但 `qwb-data/functional/` 里**没有** `hf.yaml` ——
HF 不是泛函数据，它是"没有 XC 项 + `α_hf = 1`"。在此之前 `JobInput{method_name:"hf"}`
会以"unknown functional hf"失败，也就是 K2 文档写的用法**根本走不通**。

决定：引擎里唯一一处翻译（`lib.rs::functional_name_from_method`）：`"hf"`（大小写不敏感）
→ 空名字，再由 `terms_and_hf_exchange` 走"空 terms + α_hf = 1"。**不在数据层伪造 `hf.yaml`**：
那会让注册表里出现一个不是泛函的"泛函"，K1 的 `functional` schema 也要求 components。

验收：H2/STO-3G 的 HF 单点 = −1.116759（外部参考，容差 1e-3），见
`qwb-engine/tests/t8_opt_jobtype.rs` 与 `qwb-studio/tests/test_engine_opt.py`。

### ④ GUI 的下拉框从哪来

决定：从 `qwb-data/registry.yaml` 读（`qwb_studio/data_catalog.py`）。理由：基组/泛函/
网格名是**数据**，写死在界面里就会落后；而且"界面上能选的就是数据里有的"天然成立 ——
`b3lyp` 不在注册表里（`requires.laplacian = true` 被 K1 的 phase-1 门禁拒绝），
下拉框里就不该出现它。元素列表按所选基组的 `elements:` 过滤，免得用户选 Cr 之后
才拿到"data load failed"。

`freq` **不提供**：`JobType::Freq` 还没接到 `EngineBackend`（`hessian::numerical_hessian`
是有的，F-01/F-02 的测试直接用），给一个必然失败的选项等于骗用户。给了的是 `sp` / `opt`。

### ⑤ 崩溃后重启：`running` 的任务算什么

T7 的 Rust 侧 `qwb batch` 对"队列里停在 running"的处理是**报告但不改状态**
（它的 `QueueEntry` 没有 reason 字段，只能等人用新 task id 重提）。Python 侧的
`QueueEntry` 有 `reason`，于是可以让它落终态。

决定：GUI 启动时 `GuiProject.restore()` → `Scheduler::recover()`，把 `running` 落
`failed`（reason 写明 interrupted），`queued` 保持 `queued` 以便"运行队列"接着跑。
依据：K3 没有 `running → queued` 这条边，`running → failed` 是合法边；落终态也符合
"崩溃后重启恢复未完成视图"的字面意思 —— 用户能看到**哪些任务被打断了**，而不是看到
一个永远不会动的 running。

## 四十二、ECP 落地时踩到的四件事（2026-10-26）

T5 要把 ECP 从"数据 schema 有了、引擎没接"变成"能算 CuH"。过程里踩到四件值得记的事。

### ① spec 的两处数据事实错误（已按用户批准更正）

* T5 写「Cu `n_core_electrons == 28`、`z_eff == 1.0`」。真实 LANL2DZ 的 Cu 是 **10 芯**
  （`[Ne]` 芯，3s/3p 留在价层，Hay–Wadt 的 "K to Au including the outermost core orbitals"，
  DOI 10.1063/1.448975）→ `z_eff = 19`。28 芯会只剩 4s 一个价电子，与 BSE 导出的
  `[3s3p2d]` 价基自相矛盾。
* T5 写 ZnO 用 `def2-ECP`。**Zn 的 def2-ECP 不存在**：BSE 的 def2-ecp 从 Rb（Z=37）才开始，
  def2 系列对 3d 元素是全电子。经用户批准，ZnO 改用同族 LANL2DZ（Zn 18 芯 / `z_eff = 12`）。

教训：冻结的验收判据里如果写的是"数字"，落地前一定要拿一手数据核一遍；错的不是代码而是判据时，
**停下来问人**比悄悄按判据造数据强（这也是 §10.3"只有改冻结语义才停"的边界）。

### ② "局域通道 = 最大 l"这个约定必须显式写出来

BSE/EMSL 的 ECP 数据给 `l = 0..L` 几个通道，其中 **`L` 是局域**，其余是投影：

```text
V_ECP = V_L + Σ_{l<L} (V_l − V_L) P_l
```

Cu 的 `L = 2`，Zn 的 `L = 3`（f 通道！于是 Zn 的 d 通道反而是投影 —— 这一点如果不写清楚，
读代码的人会以为 d 也走局域）。数据文件里把 `local_part.id` 写成
`"l=2 (BSE local channel: the highest l in the export)"`，`notes` 里再说一遍；
`EcpOperator::from_ecp` 只从 K1 的 `local_part` / `nonlocal_parts` 读，不再自己猜。

另外：BSE 的 `r_exponents` 是 `r^n`（不是 Stuttgart 原始表的 `r^(n-2)`），§8.2 要求的
`r_power_convention` 显式字段就写 `"r^n"`，加载器看到别的值直接报错而不是猜。

### ③ 一中心之外没有解析式，所以两条实现互相咬

ECP 矩阵元 `⟨μ|V|ν⟩` 里，`V` 是**以 ECP 原子为中心**的球对称算符：

* **一中心**（μ、ν 都在 ECP 原子上，绝大多数矩阵元在这里）：有闭式 ——
  球对称 ⇒ 只有 `(l,m)` 相同的元非零，径向是 `∫ r^m e^{−γr²} dr`。写成
  `one_center_matrix`。
* **异中心**（μ 或 ν 在别的原子上）：一个高斯在另一个中心上的球谐展开是**无穷级数**，
  没有闭式。生产路径改成**半数值**：在 ECP 中心上取径向 × 角向求积，非局域部分用实球谐投影
  `⟨μ|ΔV P_l|ν⟩ = Σ_i w_i r² ΔV(r_i) Σ_m c^μ_{lm}(r_i) c^ν_{lm}(r_i)`，
  这样一中心与异中心用**同一套公式**，不需要那个无穷展开。

两条实现对咬：Cu 2.7e-14、Zn 3.9e-14（判据 1e-8）；异中心没有解析对照，用求积加密
（fine vs veryfine 1.8e-14、veryfine vs 再密一级 6.4e-14）。

**诊断用了最朴素的一招，但最有效**：把 V(r) 设成常数 1，两条实现都必须等于重叠矩阵。
一跑就露出解析实现大了 √(4/π) 倍 —— 根因是 `Γ(3/2)` 被当成 1（`gamma_half` 的基只写了
Γ(1/2) 与 Γ(1)）。这类"用已知答案的特殊情形当探针"的办法，比盯着公式看快得多。

### ④ ZnO 一开始不收敛：不是 ECP 的算术错，是初猜（以及 LANL2DZ 本身）

**结论先说**：CuH 收敛（−213.9069054186 Ha）；ZnO 起初**不收敛**，定位到根因后用
**费米展宽退火**（第一级 SCF 退路）救回来了 —— 前 20 步按 T = 0.3 Ha 的费米占据跑，
之后切回整数占据，**23 步收敛**（E = −103.7069534201 Ha，r = 1.70 Å）。
退火后的整数占据解与展宽参数**无关**：T = 0.1/0.2/0.3/0.5、步数 10/20/40/80 给同一个能量
（逐位相同），说明展宽只是帮它走过坏的初始区域，不是在改能量定义。

定位过程（都有证据）：

1. Zn 原子（LANL2DZ，12 价电子）**收敛**：E = −44.240656 Ha，3d 五重简并在 −0.55 Ha
   —— 说明 ECP 矩阵元与 z_eff 接线没有把体系搞坏（I-05 的解析对照也到 1e-14）。
2. O 原子（LANL2DZ 全电子，8 电子，闭壳层受限）**不收敛** —— 这**不是 bug**：
   O 的基态是 ³P（两个单占 p 轨道），闭壳层受限的 O 原子本身就是伪解。
3. 于是 ZnO 从伪组态出发：`QWB_SCF_TRACE=1` 逐迭代看，能量在 −119…−121 Ha 振荡、
   `max|dP| ≈ 1`（占据在几个组态之间跳）。
4. 多初猜（5 个 `initial_guess_scale`）、密度阻尼（0.05–0.4）、静态能级移动（0.1–2.0）、
   四个网格等级、PBE/SVWN5 —— 都**没**收敛。
5. **费米展宽退火收敛**：`smearing_steps = 20` + `smearing_temperature = 0.3`。
   机理是标准的：分数占据让密度连续移动，把体系从"O 原子伪组态"这个吸引域里带出来；
   20 步之后占据回到整数，剩下的 3 步就收敛了。

为此给 `RksOptions` 加了三个**默认关闭**的确定性选项（`damping`、`level_shift`、
`smearing_steps`/`smearing_temperature`），引擎在第一级 SCF 失败后**先试退火**
（最便宜、最治本），再退到"多初猜"，最后是"阻尼 Roothaan"。三条都写进 `Reporter` 日志，
而且全部确定性（固定温度/步数/初猜序列，无随机化）。

**踩到的坑**：第一版退火把"收敛判据"也用在展宽阶段，于是它在**展宽态**上判"收敛"，
给出 +29.9 Ha 的垃圾能量（还很快乐地报成功）。修法：`step >= smearing_steps` 才允许判收敛。
这类"新功能自己给自己发合格证"的错误，只能靠断言（这里是比较参考 csv）挡住。

**关于 reference csv**：T5 要求 ZnO 与 `tests/reference/*.csv` 差 < 5 mHa。PBE/LANL2DZ 的 ZnO
总能量**没有**可引用外部值（CCCBDB 没有 ECP 系列），所以 `zno_lanl2dz_pbe_ecp.csv` 的来源
如实标 `internal-independent-path`：它是回归钉，钉"ECP 接线 + 退火不会被后续改动悄悄改掉"，
**不声称**是外部基准。物理佐证另记：本项目 r_e = 1.85 Å，实验 1.704 Å，偏长 0.15 Å ——
这是 LANL2DZ 对 ZnO 的已知系统性偏差（Zn 3d / O 2p 平衡差），不是实现问题。

## 四十三、两条"外援"：PySCF 当尺子，退火当撬棍（2026-10-26）

这一轮收口了 T2 和 T6 的最后一块，两个都不是靠改实现，而是靠**换方法**。

### ① T2：外援是 PySCF，但入口在 WSL

T2 的判据是"能量与参考 csv 差 < 1 mHa"，而 csv 一直是 `internal-independent-path`
—— 只能证明可复现，不能证明正确。根子是 **Windows 侧装不上 pyscf**（Python 3.12 没有
wheel，源码构建失败）。这次换了个地方：**WSL 的 Ubuntu 22.04 自带 Python 3.10**，
`python3 -m pip install --user pyscf` 直接拿到 2.14.0（Linux wheel 齐全）。

于是同一几何/模型化学用 PySCF 独立算了一遍：**-76.271970822413 Ha**（dft.grids.level = 3、
conv_tol 1e-10、PySCF 自带 def2-SVP）。本项目 grid-normal 是 -76.2719421662，
差 **2.87e-5 Ha** —— 判据 1 mHa，通过。csv 的来源标注据此从 internal 改成 external。

边界（§14 #12）讲清楚：PySCF 只用来**产数字**，代码与数据一个字节都没进本仓库；
def2-SVP 的指数/系数仍来自 BSE 导出（D-04 逐项 diff < 1e-12），本项目的实现与 PySCF
没有任何依赖关系。复现脚本是 `scripts/pyscf_reference.py`。

顺带一提，这条通道以后还能用来给别的判据找"第二个代码的同一个数"（T4 的频率、T6 的苯
都可以）。但它是**尺子**，不是我们的实现。

### ② T6：苯的 PBE 收敛靠多初猜，而"退火"差点骗了我们

苯的 PBE 单初猜 DIIS 400 步不收敛（B3LYP 只要 16 步）。上一轮为 ZnO 做的**费米展宽退火**
看起来是现成的解法，实测也确实"收敛"了 —— 23 步，E = -209.9115 Ha。
**但它比 CCCBDB 的 -229.117005 高 19 Ha**：那不是精度问题，是停在了完全错误的态上。

真正的解法是**多初猜**：`initial_guess_scale = 1.5` 只要 15 步就收敛到
-229.1170417 Ha（差 **0.04 mHa**）。教训有两层：

1. **"SCF 收敛了"不等于"算对了"**。这次是 CCCBDB 这个外部尺子把假收敛照出来的
   —— 如果苯没有外部参考值，我们很可能就把 -209.9115 记成"通过"了。
2. **退火只解决"从坏初值出不来"，不保证落到对的解**。它是撬棍，不是尺子。

所以引擎的 SCF 退路顺序订正为**多初猜在前**（每次尝试给 `min(scf_max_iter, 60)` 步的预算），
退火在后，而且**退火成功之后还要做一次有界多初猜交叉验证、取能量更低者**。
ZnO 仍然只能靠退火（多初猜 5 个尺度全失败），所以两条路都得留 —— 只是先后与验证关系定死了。

另外记一句网格敏感度：苯的 B3LYP/PBE 在 grid-coarse 上差 -0.01 / -0.04 mHa，
在 grid-normal 上反而是 -1.16 / -1.33 mHa（都在 2 mHa 判据内，但 coarse 更接近）。
这和 G-01 记的"网格权重导数没算"是同一类问题的两个侧面，等要做更细的能量时一起解决。

## 四十四、第三方数据不进仓库：配方入库，文件按需取回（2026-11-05）

**触发**：把仓库推到 GitHub 之后，`qwb-data/basis/` 与 `qwb-data/ecp/` 里的 7 个文件
（STO-3G / def2-SVP / def2-TZVP / 6-311G(d,p) / LANL2DZ + 两个 LANL2DZ ECP）是
从 Basis Set Exchange 导出的第三方数据。`DATA_LICENSES.md` 里自己就写着 LANL2DZ 的 ECP
是 `redistribute_ok: false`（原始论文没给明确的再分发条款，§14 #20）——
**这等于自我矛盾**：许可标记说不能再分发，仓库里却躺着这两个文件。

**决定**：仓库只提交**配方**与**摘要钉**，文件由使用者从上游取回。

- 新增 `qwb-data/sources.json`：每条数据的 `fetch`（BSE 的 basis 名 + 元素）、
  `transcribe`（名字/版本/引用/许可/形态）、`sha256` 钉；
- `registry.yaml` 不变（K1 的索引仍然列出全部条目与摘要）——
  所以"数据结构"没有变，变的只是"文件从哪来"；
- 取回实现只有一份：`qwb-studio/qwb_studio/bse_data.py`（转录）+
  `datafetch.py`（下载 → 转录 → 调 `qwb data sign` 打戳 → 核对钉 → 原子替换）。
  `scripts/bse_to_qwb_data.py` / `bse_ecp_to_qwb_data.py` 从两个**各有一套转录逻辑**的脚本
  降级成薄封装——转录规则一旦有两份就一定会漂移，而漂移的后果是静默错数；
- 三条入口指向同一实现：`qwb data install`（Rust CLI 调度 Python）、
  `python scripts/fetch_data.py`（独立脚本）、GUI 的 Data 页（工作线程里跑）；
- **自动取回**：`run` / `batch` 开始前检查，缺则按输入需要的取回（`--for-input` 语义，
  只下缺的那几个）。取数失败只 warning 不阻断——缺 LANL2DZ 不该挡住一个 STO-3G 的作业；
  真正需要它的作业会在 `get_basis` 拿到带取数命令的错误（退出码 3）。

**加载器必须跟着改**：`Registry::open` 原本"任一条目文件读不出就整体失败"。如果保持原样，
一个还没下载数据的 clone 连 STO-3G 的作业都跑不了。现在：
`sources.json` 里的路径缺失 → 跳过并记进 `Registry::missing_data()`（正常状态），
其它文件缺失 → 仍然是硬错误（数据根被裁剪过，静默跳过会让"少了一个泛函"变成运行时怪错误）。
`qwb data verify` 也把缺失的第三方文件记成**该文件的**失败报告（`16 checked / 9 passed /
7 failed`，而不是把整个清单标红），消息里直接给 `qwb data install`。

**核对**：本次把 7 个文件全部删掉再重新取回，**7/7 摘要与钉逐位相同**
（`fce3af14…` / `177675559…` / `263b684f…` / `cfda92e2…` / `bc14a7e1…` /
`a44df71f…` / `55b33916…`）。所以 `registry.yaml` 的钉、结果目录里的
`data_snapshot.json`、以及之前记的所有验收数字都仍然有效——这条是设计约束，
不是巧合：摘要算的是"规范化内容"，与文件从哪来、怎么排版无关。

**顺带解决的两个坑**：

1. BSE 把 Pople 系列的极化函数标成 `region: "polarization"`（不是 `valence`）。
   转录器的 `region` 白名单原本只有 `valence`/`unknown`，于是 6-311G(d,p) 直接转录失败。
   `region` 只是**标签**，不是"导出被裁剪过"的证据；真正表示裁剪的是 `core`/`semicore`，
   那两个仍然显式拒绝。
2. `sources.json` 里 LANL2DZ-Zn 的 citation `url` 一开始误写成 `…/api/basis/lanl2dz/`
   （API 端点而不是基组页），与另外 6 条不一致，导致 Zn 的 ECP 摘要对不上。
   这条是**清单错误**，不是上游变了——也说明"摘要不符"的报错方向是对的：
   它逼人去解释差异，而不是静默接受。

**D-15 也跟着稳定了**：`scripts/gen_data_licenses.py` 原来扫描磁盘上的数据文件，
数据不在仓库里就会让 `DATA_LICENSES.md` 随下载状态漂移。现在缺失的第三方文件从
`sources.json` 合成同样的行（名字/版本/许可/引用/摘要钉全都来自清单），
**"文件在本地"与"不在本地"渲染结果逐字节相同**（实测两次 diff 一致）。

## 四十五、阶段二规划：把"模仿 Jaguar"拆成允许失败的台阶（2026-11-06）

阶段一收口后，下一步该做什么需要一份和 `project.md` 同构的规范。这次的取舍有三个：

**① 覆盖 Jaguar 的"方法广度"，但不承诺全部做成。**
Jaguar 的能力清单（[产品页](https://www.schrodinger.com/platform/products/jaguar/) /
[Wikipedia](https://en.wikipedia.org/wiki/Jaguar_(software))）里，阶段一明确排除了开壳层、
meta-GGA、range-separated、色散、相关方法、激发态、溶剂、反应路径、谱学、pseudospectral。
阶段二把它们按"能不能验收"重新分类，而不是按"想不想做"：`✅ 必做` / `⚠ 可降级` /
`stretch 可失败`。这一条是**写进规范的结构性让步** —— 阶段一的铁律是"不允许做不到"，
如果阶段二照抄，第一个 `ps` 或 `pbf` 就会把整个阶段卡死。所以 `project-phase2.md` §2.5
定义了 kill criteria 与记账格式：做不到要交**实测数字 + 差距 + 卡点**，而不是含糊的"很难"。

**② 契约继续冻结，但新增 K7–K10。**
K1–K6 的语义一个都不动，只做加性扩展（全部 `Option`/新 feature 词/新可选结果块，旧输入
与旧结果目录继续工作）。真正需要新契约的是四件事，各自都有"判据"而不是"接口"：

- **K7 响应与性质**：激发态/NMR/极化率/多极的结构 + 三条不变量门禁
  （f-sum rule、length-gauge 一致性、转动协变）；
- **K8 溶剂化**：模型选择与能量分解（静电/空化/色散/排斥四项必须能逐项对账）；
- **K9 开壳层与相关方法**：`⟨S²⟩` 与自旋污染**必须报出来**（沉默是不可接受的）；
- **K10 数值路径等价**：这是最要紧的一条 —— 任何"更快但更糙"的路径（RI、pseudospectral、
  更粗的网格）都要与解析路径在声明的容差内等价、随精度等级单调收敛、并行确定性，
  并且**用了近似必须留痕**（`numerics_report` 进 `result.json`）。

阶段一排除 pseudospectral 的理由是"它会搅浑验收"；阶段二的做法不是"现在敢做了"，而是
**把它关进 K10 的等价性门禁里**，允许它失败（`IN-03` 是 stretch，不进任何里程碑依赖）。

**③ 五层验证，新增的两层才是阶段二的真正难点。**
单元 / 物理极限 / **数值路径等价** / **物理不变量** / 基准集。前两层阶段一就有了；
第三层是"近似对不对"，第四层是"实现对不对"（与近似无关的恒等式）。举例：
CIS/TDA 的 f-sum rule、NMR 的长度规范一致性、解析 Hessian 与数值 Hessian 的独立对照
（再加频率 vs 实验，防止"互相对照变成同错"）。

**记账**：阶段二用**独立的 `docs/status-v2.yaml`**（阶段一的 `status.yaml` 只读作基线），
`scripts/check_status.py` 直接能用（它就是"任意路径的账本校验器"），并且已加进门禁
（`verify-r60`，26/26）。这样阶段二的第一天就有可执行的记账，而不是等第一个 WP 做完再补。

## 四十六、阶段二契约轨道：三个"计划里没写对"的地方（2026-11-06）

KV-01..KV-03（K7/K8/K9 的契约 + K1 的溶剂字段）落地时，规范里有两处与实际约定冲突、
一处没考虑到后果。记下来，因为下次还会遇到同类问题。

**① 计划说"K7 由 schemars 生成 schema"，但这违反 C-03 的约定。**
`engine-api` 是**传递类型 crate**，C-03 明确要求它保持**零 schema 依赖**（K2 不生成
JSON Schema，K1 才生成）。所以 K7–K9 的结果块只能走 C-03 建好的那条路：
`qwb-contracts/studio/result.schema.yaml` 手写文档 + `qwb-io/tests/k3_schema_docs.rs`
把"文档说的字段集"和"实际序列化出来的键集"逐字段对齐。
教训：**"契约先行"不等于"每份契约都用同一套工具"**；先看清该轨道已有的约定，再决定产物形态。
（已回填 `project-phase2.md` §4.1/§6.1。）

**② 计划没意识到 `TaskOptions` 是 `non_exhaustive`，下游写不了 struct literal。**
新选项得配 builder（`with_scf_type` / `with_mp2` / `with_excited_states` /
`with_solvent_model`），否则**集成测试根本挂不上选项** —— 这不是风格问题，而是
"契约能表达"和"调用方能构造"之间的缺口。`JobResult` 一直是 builder 风格，这里只是把
同一条规矩补到 `TaskOptions` 上。

**③ 最要紧的一件：字段能解析 ≠ 选项被尊重。**
契约一旦能让用户写出 `scf_type: uks`，用户就会去写。如果引擎静默忽略它，用户会拿到一个
**看起来成功的闭壳层 RKS 结果**，然后以为是 UKS 的结果 —— 这比报错危险得多
（`project-phase2.md` §10.3 明令禁止的"静默降级"）。
所以这一轮特意加了 `qwb-engine` 的 `reject_unimplemented_options`：开壳层 `scf_type`、
`mp2`、`excited_states`、非真空 `solvent_model` 一律 `Unsupported`（退出码 4），
**消息里带负责它的 WP 编号**（SC-01 / SC-04 / RS-02 / SV-01），让"还没做"和"不支持"分得开。
判据刻意比"字段非空就拒"更细：与阶段一行为等价的写法（`rks`/`rhf`/`vacuum`）**放过**，
否则旧输入会被无故拒绝 —— 加性契约的意义就是旧输入一个字节都不用改。

**顺带一个设计上的取舍**：`Solvent` 没有加 `model` 字段。K1 已经有 `cavity_model`，
再加一个就是两个真值源；阶段二只补它真正缺的四样（光学介电常数、半径集的声明、
表面张力、离子强度）。K2 侧的 `SolventModel` 是**输入词汇**（engine-api 不能依赖 K1 crate），
由引擎映射过去 —— 与 `GridLevel` 在两侧各有一份是同一个既定模式。

**一个小坑**：`SolvationResult::new` 一开始有 8 个位置参数，`clippy::too_many_arguments`
直接红。这不是"加个 allow"的事：表面积/体积/tesserae 本来就是同一件事（空腔几何），
抽成 `CavityGeometry` 之后参数降到 6 个，校验也集中到一处。**编译器的唠叨有时是设计信号**。

## 四十七、阶段二 M1 的验收里有一处物理写错了（2026-11-06，开工前发现）

契约轨道 KV-01..KV-05 收口后，下一步是 M1（开壳层）。设计 UHF 时发现 M1 的断言里有一条
**照现在这样写永远过不了**：

> M1 断言：O2 三重态 `⟨S²⟩` 与 2.0 差 < 1e-6。

`⟨S²⟩ = 2.0` 精确成立的是**纯净自旋态**。UHF/UKS 对 O2 会因为 π* 的简并而**自旋污染**
（文献里 UHF/6-31G* 的 O2 `⟨S²⟩` 约 2.1），所以"差 < 1e-6"这个判据对 UHF/UKS 不可能成立。
能精确给出 2.0 的是 **ROHF**（限制性开壳层，按构造就是纯自旋态）。

这不是笔误级别的问题：照抄这条验收，agent 只有两条路 —— 要么把 `⟨S²⟩` 硬写成 2.0
（伪造），要么永远标 blocked（卡死）。两种都不能接受。

**处置（下一轮开工时按这个改 §6.5/§7/M1）**：

1. 把 SC-01 拆成两个包：
   - `SC-01`：**UHF** 的自旋机制（双套密度、J 用 P_α+P_β、F_σ = H+J−K_σ、⟨S²⟩ 与污染量、
     闭壳层退化一致性）。验收用**外部参照**（PySCF 黑盒跑同一体系同一基组）与
     "H2 的 UHF ≡ RHF" 这类不依赖文献的恒等式。
   - `SC-01b`：**ROHF**（纯自旋，`⟨S²⟩ = S(S+1)` 精确到 1e-6）+ **UKS**（自旋分辨 XC：
     交换用 `½[E_x(2ρ_α)+E_x(2ρ_β)]`，相关项要 VWN5/PBE-C/LYP 的自旋插值）。
2. M1 的断言改成"分层"的：
   - 闭壳层退化：H2/STO-3G 的 `uhf` 能量 == `rhf` 能量（< 1e-8），`⟨S²⟩ < 1e-8`；
   - 自旋纯度：O2 的 **ROHF** `⟨S²⟩ = 2.0`（< 1e-6）；
   - 污染报告：O2 的 **UHF** `⟨S²⟩` 必须**报出来**且与外部参照一致（不是"必须等于 2"）；
   - OH 双峰：UHF 收敛、`spin_contamination` 打印，且与外部参照同值。
3. 这条也说明"验收判据里出现精确等式时，先问一句：这个精确性是**方法的性质**还是
   **物理的巧合**"。`⟨S²⟩ = S(S+1)` 是 ROHF 的性质，不是 O2 的性质。

**同时记一条工程顺序**：UKS 比 UHF 难得多（要给 VWN5/PBE-C/LYP 写自旋插值并逐个对照），
所以 M1 先走 UHF/ROHF，UKS 排在 `SC-01b`。这不是降级验收：UHF/ROHF 本身就是 Jaguar 支持的方法，
而且它们是 UKS 的对照组（UKS 在"纯 HF 极限"下必须退回 UHF）。

## 四十八、UHF：三件事，每一件都是外部参照逼出来的（2026-11-06）

M1（开壳层第一步）落地。回头看，这一轮有三次"我以为对了、参照说不对"。

**① 能量公式漏了一个 H。** 我按闭壳层的习惯写成 `E = ½ Σ_σ Tr[P_σ F_σ]`，
但自旋通道的 Fock 是 `F_σ = H + J − K_σ`（含 H），正确式子是
`E = ½ Σ_σ Tr[P_σ (H + F_σ)]`。H2/STO-3G 立刻差出 1.25 Ha —— 这不是"精度问题"，
是公式少了一项。**代价最小的一次纠错**：外部参照（PySCF 的 −1.116759307396）一摆，
错误无处可藏。

**② O2 的两个解：换初猜差 0.255 Ha。** 第一版收敛到 −147.378901，PySCF 给 −147.633970。
先怀疑自己（漏项？占用数错？）：不是。查 PySCF 用 `init_guess='hcore'` ——
**它落在同一个 −147.378901175973**（差 2e-8）。所以我们的实现是对的，问题在初猜：
core guess 的数值噪声轻微破坏 π_g 简并，SCF 把破缺放大到另一个（较高的）解。

解法是**自旋平均的原子密度初猜**（SAD，Van Lenthe–Baerends）：对每个原子用同一套基组
做一次原子 SCF，把**总密度对半分**给 α/β 再叠加。球对称的初猜不破坏简并，于是落到
变分极小（−147.633969642，与 PySCF 差 3.4e-8）。

顺手记一条**方法学**：SAD 有两种写法 —— "自旋分辨的原子密度"（O 的 ³P 有 2 个单占 p，
α/β 不同）与"自旋平均"。我先写了前者，O2 收敛到 −147.484（仍然偏高 0.15 Ha）；
换成平均才到变分极小。**经典的 SAD 是平均版**，不是分辨版 —— 因为初猜的职责是"给出
对称、合理的密度分布"，不是"猜自旋态"。

**③ ⟨S²⟩ 比能量敏感一个数量级。** OH 在 `(1e-8, 1e-6)` 的收敛判据下与 PySCF 的
`⟨S²⟩` 差 3.4e-5，能量却已经对到 1e-8 —— 能量是二阶量、`⟨S²⟩` 是一阶量。
把判据收紧到 `(1e-11, 1e-10)` 后差 5e-10。**所以断言 `⟨S²⟩` 的测试必须自带紧判据**，
不能用默认值。

**关于验收本身**：M1 原来那句"O2 的 `⟨S²⟩` 与 2.0 差 < 1e-6"已经被改掉（四十七）。
这一轮把 SC-01 与 SC-01b 拆开、加了 M1b，并把"污染量必须报出来且与外部参照一致"
写成断言 —— 这比"精确等于 2.0"弱，但它是**真的**。

## 四十九、ROHF 的等效 Fock 我没搞对（blocked），以及一个真正的进展（2026-11-06）

**先说结论**：ROHF（纯自旋）没做成，按 §2.5 记 `blocked`，代码已从工作树移除（git 里有）。
UKS 的自旋基础（VWN5 自旋插值）做成了，6 例全绿。

### ROHF：差 0.41 Ha，但闭壳层是对的

三版实现、两个失败模式，都记了数字：

| 版本 | 等效 Fock | 结果 |
|---|---|---|
| v1 | C-V = F_C，C-O = F_β，O-V = ½F_α | 400 步不收敛 |
| v2 | 按梯度 2:1:1（C⊕V = 2F_C，C-O = F_β，O-V = F_α） | **收敛到错驻点**：O2 −147.2212（差 0.411 Ha）、OH −73.239（差 1.12 Ha） |
| v3 | 统一尺度 1:1:1 | 400 步不收敛 |

闭壳层情形（H2）三个版本都精确 ≡ RHF —— 所以双套密度、J/K、能量公式、DIIS 都是对的，
**错的只是 C-O 与 O-V 混合块的处理**。

定位到的两个具体原因：

1. **缩放不能直接按梯度系数 4:2:2 套**：`F_eff` 的本征值同时决定占据顺序（前 n_β 当闭壳层、
   再 n_s 当开壳层）。把闭⊕虚块乘 2 之后，闭壳层与开壳层的能级不可比，aufbau 会把闭壳层
   轨道误判成开壳层 —— 这正是 v2 那个 0.41 Ha 解的直接来源（我一开始以为是"F 构造错了"，
   其实 F 没错，是**占据被判错**）。
2. 统一尺度又让迭代矩阵条件数坏掉（v3 不收敛）。

下一步两条路我都写在 `docs/status-v2.yaml` 的 SC-01c 里：A. 回到 Guest–Saunders 原文/
Faegri–Manne 的耦合系数表重推 C-O/O-V 块，并**按轨道身份跟踪占据**（不靠本征值排序）；
B. 改成"轨道旋转直接优化"——我推导的那三个块公式（闭↔虚 `2Tr[δP_C F_C]`、闭↔开
`Tr[δP_C F_β]`、开↔虚 `Tr[δP_O F_α]`）本身是可以用有限差分验证的，直接拿它们做线搜索
就不需要正确的等效 Fock。

**为什么直接记 blocked 而不是继续试**：再试下去就是"调参数直到能动"，那和"拟合验收"没区别。
有明确的两条技术路线、有实测数字，这是可以交给下一轮（或人类）的 `blocked`。

### 真正做成的那一半：VWN5 的自旋插值

UKS 的 XC 侧有好几块，其中最"公式密集"的一块是 **LSDA 相关能的自旋插值**：

```text
ε_c(ρ_α, ρ_β) = ε_c^P(r_s) + [ε_c^F(r_s) − ε_c^P(r_s)] · f(ζ)
f(ζ) = [(1+ζ)^{4/3} + (1−ζ)^{4/3} − 2] / (2^{4/3} − 2)
```

数据侧**不需要任何改动**：`svwn5.yaml` 里 `vwn5_f_*`（铁磁）与 `vwn5_a_*`（α_c）参数
本来就有，只是闭壳层路径从来没读过它们（那条路径把 ζ 当成 0）。所以这一轮做的是
"把已有的数据接上" + 把导数算对。

六条断言里最有价值的是**有限差分**：`∂ε/∂ρ_α`、`∂ε/∂ρ_β` 与中心差分差 < 1e-9，
包括 ζ = 0.9 / 0.98 的近铁磁点（那里 `f'(ζ)` 的 cbrt 项最容易写错）。
另一条是 ζ = 0 时**逐点退回闭壳层值**（< 1e-12）——它保证"UKS 在闭壳层极限下等于 RKS"
这条退化一致性有基础，而这是 M1b 的判据之一。

**教训（与四十八呼应）**：多写一组"极限/差分"断言，代价是几十行，收益是"公式对不对"
当场就能看出来，而不是等整个 UKS 装好之后在一个 0.4 Ha 的偏差里找原因。

## 五十、`svwn5.yaml` 其实是 VWN **RPA**，不是大家叫的 VWN5（2026-11-06）

做 UKS 的逐点对照时发现的，值得单独记一笔，因为它同时解释了两件旧事。

把我们的 `LdaSvwn5` 与 PySCF（libxc）逐点比，一开始怎么都对不上：同一个
`(ρ_α, ρ_β)` 上我们的 ε_c 比 libxc 的 `VWN5` 更负，差值还不小（rs ≈ 0.74 处 0.02 Ha/e）。
试了三种插值形式（两端插值、PW92 的 ζ⁴ 形式、α_c 缩放）都对不上，直到把 libxc 的
**所有** VWN 变体都拉出来比：

```text
VWN5        : ε_c = -0.067375843815      ← PySCF 的 'SVWN' / 'VWN' 走的是这个
LDA_C_VWN_RPA: ε_c = -0.087274042662     ← 我们的公式 + 数据里的参数 = 这一行（差 1e-12）
LDA_C_PW_MOD: ε_c = -0.067031740018      ← PBE 的 LDA 基
```

也就是说：`svwn5.yaml` 里的 `vwn5_p_*` / `vwn5_f_*` / `vwn5_a_*` 三组数正是 libxc
`lda_c_vwn_rpa` 的参数集，我们的实现也是**忠实的 VWN RPA**（两端插值
`ε = ε^P + (ε^F − ε^P) f(ζ)`，逐点对照 11 个密度对差 < 1e-12）。而"VWN5"这个名字
被社区用在另一个参数集上（libxc 的 `lda_c_vwn`），两者相差 0.02 Ha/e。

**为什么不改名字/参数**：阶段一的数据与文档、K1 的 `functional` 标识、CCCBDB 的
LSDA 参考行（`H2O,LSDA,STO-3G = −74.939072`）全都挂在 `svwn5` 这个名字上，而且
CCCBDB 的 "LSDA" 实际上与 **RPA** 版本一致（我们的 −74.9281 差 0.011 Ha，来自几何），
与 libxc 的 VWN5（−74.7322）差 0.21 Ha。改名会让阶段一的参考值全部失去锚点。

**代价与对策**：凡是"与 PySCF 的 SVWN5 对照"的地方，都必须写成
`LDA_X,LDA_C_VWN_RPA`。`scripts/pyscf_uks_reference.py` 与
`qwb-xc/tests/reference/spin_xc_pointwise.csv` 的 `note` 列都写明了这一点。

**另一件旧事因此得到解释**：OH 的 UKS + `svwn5` 在 PySCF 里（DIIS / 能级移动 / Newton
三种策略）都不收敛，我们的实现在 400 步内也不收敛。RPA 相关的低密度行为本来就很差
（它的关联势比 QMC 参数化更早发散），所以这不是我们的 bug；已如实记进
`docs/status-v2.yaml` 的 SC-01b 与 `uks_open_shell.csv`（能量列写 `nan`，不冒充参考值）。

## 五十一、`pbe_mu` 抄了 6 位有效数字，代价是 2.6e-5 Ha（2026-11-06）

O2 的 UKS/PBE 一开始与 PySCF 差 2.6e-5 Ha（判据是 1e-6）。逐点对照显示
`GGA_X_PBE` 的能量对得上（1e-12）但 σ 导数差 2.3e-5 的相对量，这个数正好等于
`pbe_mu` 的相对截断误差。

追下去发现：同一个 `pbe.yaml` 里 `pbe_beta = 0.06672455060314922`（17 位），
而 `pbe_mu = 0.21951`（6 位）—— 但 PBE 原文里 **μ = βπ²/3 是同一组常数推出来的**，
不是独立参数。手抄 6 位等于把两个本应一致的常数写成了两个不同精度。

修法：把 μ 换成由 β 算出的 `0.21951497276451704`（Python 里 `BETA*pi**2/3`，
生成脚本算出来写进数据，不再手抄），并且 `pw_sh` 里 `pbe_mu` 的 `parameter_sources`
写清楚来源。效果：

```text
GGA_X_PBE 逐点最大差   2.3e-5 → 1e-12（σ 导数同样到 1e-12）
O2   UKS/PBE (grid-fine) −148.1376924 → −148.1377193，与 PySCF 差 5.8e-7
OH   UKS/PBE (grid-fine) −74.5739461，与 PySCF 差 1.1e-6（残差是网格）
```

数据版本 0.6.0 里顺带加了 PW92 的三组参数（`pw92_p_*` / `pw92_f_*` / `pw92_a_*`）：
自旋分辨的 PBE 相关需要 ε_c^P、ε_c^F 与 α_c 三套，闭壳层只需要第一套，
而那套以前是三个 `const` 写死在 `gga.rs` 里的。现在三套都进数据、都走同一个
`Pw92Set::energy_and_derivative`，`σ→0` 时与原来逐位相同（回归钉住）。

**教训**：数据文件里同一个物理常数出现两次、精度不同，是"看起来没错"的错误里
最难发现的一种 —— 单点测试全绿，只有拿黑盒尺子量总能量时才会露出来。

## 五十二、UKS 的自旋接口：一次求值六个通道，ζ = ±1 要夹紧（2026-11-06）

第一版把自旋接口做成"三个方法"（`energy_density_spin` / `potential_spin` /
`sigma_derivatives_spin`），很快就发现两个问题：

1. **能量与势必须来自同一次求值**。分开传切片时，"能量用 A 公式、势用 B 公式"
   这类错误在能量上看不出来（变分性会掩盖），只能在 SCF 收敛后的一阶量上露头。
   现在是一个方法：

   ```rust
   fn evaluate_spin(&self, batch: &SpinDensityBatch, out: &mut SpinXcOutput)
   ```

   `SpinXcOutput` 有六个切片：每体积能量密度、两个势、三个 σ 导数。LDA 项必须
   把三个 σ 导数**填 0**（不许留着上一次的值）。

2. **ζ = ±1 的导数是真的发散**。`φ(ζ) = [(1+ζ)^{2/3} + (1−ζ)^{2/3}]/2` 的导数在
   ζ → ±1 时按 `(1∓ζ)^{−1/3}` 发散，而 `t² ∝ 1/φ²` 把这件事带进 H。网格里
   `ρ_β` 下溢成 0 的点**精确**落在 ζ = 1 上，那里势无界。做法是 ζ 夹到
   `[−1+1e-12, 1−1e-12]`，与 `LOW_DENSITY_FLOOR` 同类的数值保护；代价是全极化点上
   `v_β` 与 libxc 差 ~1e-5（能量差 < 1e-9），所以逐点测试对 ζ = ±1 的点**只断言能量**。

   顺带一个反例：VWN 的两端插值在 ζ = ±1 处是**光滑**的（`(1∓ζ)^{4/3}` 的一阶导为 0），
   一开始我也夹紧，结果 `f′(ζ)` 差 2.6e-4、`v_β` 差 1e-5 —— 夹紧只对"真的发散"的地方做。

3. **"双倍密度"是交换项自旋标度的全部**。`E_x[ρ_α, ρ_β] = ½(E_x[2ρ_α] + E_x[2ρ_β])`
   对任何 GGA 交换都精确，所以自旋版本不需要新公式：把 `(ρ_σ, σ_σσ)` 换成
   `(2ρ_σ, 4σ_σσ)` 喂给**同一个**闭壳层实现即可（σ 也要乘 4：∇(2ρ) = 2∇ρ）。
   一次实现换来 Slater / B88 / PBE-X 三个可用，而且不可能与闭壳层路径漂移。

**一个差点留下的坑**：`ρ_σ = 0` 的通道不能靠"乘 0"处理。闭壳层实现对 ρ 有下限
（`LOW_DENSITY_FLOOR`），于是 `ε(下限) ≈ −7e-5`，而 `v_σ = ε + 2ρ_σ ε_ρ` 在
`ρ_σ = 0` 时退化成 `ε ≠ 0` —— 实测 GGA_X_PBE 的 `v_β` 在 `ρ_β = 0` 处偏了 7.4e-5。
现在每个通道显式守卫：`ρ_σ <= 0` 时能量、势、σ 导数全部严格为 0。

## 五十三、τ 通道：三个约定，每一个都能让能量错一倍（2026-11-06）

FX-01 把 meta-GGA 需要的动能密度 τ 接进管线时，撞上了三个**都不是公式**的约定问题。
三个都是被"闭式可算"的测试当场照出来的，值得连着记：

**① `energy_density` 给的是每电子 ε，不是每体积能量密度。**
闭壳层路径的能量是 `E = ∫ ρ·ε dV`，所以一个 τ 线性项必须写成 `ε = c·τ/ρ`。
第一版写成 `e = c·τ`（每体积），能量直接差 9 倍 —— 因为网格上的 ρ 在核附近
可以到 10² 量级。

**② τ 通道的矩阵元要乘 ρ。**
`E = ∫ρ ε(ρ,σ,∇²ρ,τ)` 对密度矩阵求导：
`∂E/∂P_μν = ∫[∂(ρε)/∂ρ·φφ + ρ ε_σ·∂σ/∂P + ρ ε_lap·∂∇²ρ/∂P + ρ ε_τ·(½∇φ_μ∇φ_ν)]`。
所以 τ 的系数是 **½ρ(dε/dτ)**，而 σ 的系数是 2ρ(dε/dσ) —— 两个都带着 ρ，
漏掉的话 τ 项整体偏小（第一版只写了 ½dτ）。

**③ `qwb-integrals` 的 `kinetic` 矩阵是 ½∫∇φ_μ·∇φ_ν，不是 ∫∇φ_μ·∇φ_ν。**
这是闭壳层约定：自旋求和密度 `P = 2Σccᵀ` 下 `E_kin = Tr[P·K]`。于是闭式关系是

```text
∫τ = Tr[P·K]        （不是 ½Tr[P·K]）
V_τ,μν = c·K_μν      （对 ε = cτ/ρ）
```

实测锚点（用来区分"τ 算错"与"矩阵约定不同"）：网格上 `∫φ₀² = 1.0000`（与 S₀₀ 一致），
而 `∫|∇φ₀|² = 1.52006`、`K₀₀ = 0.76003` —— **正好一半**。看到这个比值就知道
网格没错，是矩阵的约定；再往下就不用怀疑 Becke 权重了。

**为什么最后能钉到 1e-9**：选了一个线性 τ 项（`ε = cτ/ρ`），它的能量与势都有闭式解
（`c·Tr[PK]` 与 `c·K`）。用 `grid-veryfine` 时两者差 < 1e-9；`grid-normal` 上是 2.8e-9
——正好是求积误差的量级（`∫|∇φ₀|²` 在 normal 上就有 1e-7 的误差），所以断言按 veryfine 写、
并在注释里写清为什么。

**还有一条纪律**：数据声明 `requires.kinetic_density: true` 与"实现里真的在读 τ"
是两件事，引擎对两者**双向**核对（`check_meta_gga_declaration`）。不一致就
`Unsupported` —— 数据说要 τ 却没有项读它，用户会拿到一个 GGA 水平的答案却以为算了
meta-GGA；反过来则是数据对自己的需求说谎。这类"声明与实现脱节"的静默降级，
比公式写错更难发现。

**范围**：FX-01 只立管线与门禁，**没有**注册任何 meta-GGA 泛函 —— `method_name: m06-2x`
现在仍然找不到数据（DA-01/DA-02 落数据、FX-02 落实现）。自旋分辨的 `τ_α/τ_β`
也还没做，`scf_type: uks` + τ 项会被显式拒绝。

## 五十四、M06 家族：两处换算，每一处都能让数字"看起来差不多但不对"（2026-11-07）

FX-02（M06-L / M06-2X 的 meta-GGA）落地时，逐点对 libxc 的对照抓出两处换算。
两处都不改变公式的形式，只改变"用哪个密度写"和"偏导是对谁求"，但任何一处
写错都让端到端能量差到 1e-2 Ha 量级。

**第一处：M06 用每自旋的约化变量，而且动能级数的分母是 2^{2/3}·K。**

libxc 的 `mgga_x_m06l.c` 里，对**非极化**体系（ζ = 0）取

```text
x² = 2^{2/3} · σ / ρ^{8/3}
t  = 2^{2/3} · τ / ρ^{5/3}
```

而 M06 的动能级数分母是

```text
K′ = 2^{2/3} · K,   K = (3/5)(6π²)^{2/3}
```

第一版把 `t` 换成每自旋量却仍用总密度的 `K`，于是均匀电子气处 `w(t) ≠ 0`
（本该恒为 0），M06-L 不再退回 Slater 交换，增强因子偏 4%。
**判据不是"与 libxc 差多少"，而是"均匀电子气处逐位退回 Slater（< 1e-10）"** ——
这条恒等式能在不看参考值的情况下先把 2^{2/3} 这类常数钉死。

**第二处：libxc 的 `vrho/vsigma/vtau` 是"每体积"偏导，我们是"每电子"偏导。**

`qwb-xc` 的 `FunctionalTerm::energy_density` 返回**每电子** ε（FX-01 的约定：
`E_xc = ∫ρ·ε dV`），而 libxc 的 `e` 与 `vrho` 是**每体积**量。换算关系是

```text
vrho_libxc   = ε + ρ ∂ε/∂ρ
vsigma_libxc = ρ ∂ε/∂σ
vtau_libxc   = ρ ∂ε/∂τ
```

换算前 σ/τ 通道"恰好差 ρ 倍"——这个整齐的常数倍就是线索。反过来，如果只比
能量密度（不含 ρ 因子）也会差 ρ 倍，所以逐点对照必须**同时**比 e 与三个偏导。

**为什么这两条值得单开一节**：它们在形式上都是"同一个泛函"，而真正的差别只有
约化变量的定义与偏导的基准。meta-GGA 的参数（M06-2X 有 38 个）越长，越容易把
误差归给系数抄错；实际这一轮的两处错都在**约定**上，系数一个没错。
判据的设计也因此固定下来：**先用不依赖参考值的恒等式（均匀电子气 → Slater）
钉约定，再用逐点对照（< 1e-9）钉系数**。

## 五十五、f 球谐变换漏了一步换算：MP2 验收顺手抓出来的老 bug（2026-10-27）

SC-04 的验收要用 def2-TZVP 看基组单调性，于是把 H2O/def2-TZVP 的 HF 拿去和
PySCF 比 —— 差 **2.7e-6 Ha**，而同一套代码在 def2-SVP（只有 d）上差 1e-9。
一个只在对 f 壳层时才出现的误差。

**定位过程（每一步都是可判定的小实验，不是猜）**：

1. **看折线**：把 def2-TZVP 里某一 `l` 的壳层删掉再算，删 f 之后两边差回 1e-9，
   删别的不行 ⇒ 问题在 `l = 3`。
2. **拆能量**：把我们的 HF 拆成 `Tr(PH) + E_2e + E_nuc`，与 PySCF 的同一拆解对比。
   两边的 1e 与 2e 各差 ~3e-4、符号相反、几乎抵消 ⇒ 不是"某个积分错了 3e-4"，
   而是**两边收敛到的密度略有不同**（f 是纯虚壳层，所以总能量只差二阶量）。
3. **先在直角坐标里对齐**：把我们的基组切成 `angular: cartesian`，与 PySCF 的
   `int1e_cart` 逐元素比 —— S、T、V、2e 块的内不变量（trace / Frobenius）全部
   一致到 1e-12（注意 PySCF 在 cartesian 模式下不会按分量归一，要先按 `S_ii` 归一）。
   ⇒ 原函数积分与收缩都是对的，嫌疑只剩球谐变换。
4. **验变换的正交归一与"与 r²p 正交"**：都过（`TᵀST = I₇`、投影 1e-16）。
5. **拿独立构造比子空间**：在**未归一**直角基下用度规 `S₀` 重新做一遍 r²p 投影 +
   Gram–Schmidt，得到 l = 3 的 `Tr(H1) = −11.555886525`（= PySCF 的球谐 f 块），
   而我们的实现给 **−12.095304264**。两者都"正交归一 + 与某三个向量正交"，
   但张成的子空间不同 ⇒ 第 4 步的判据**不充分**。

**根因**：`f_transform` 里的 `candidates` / `radial` 写的是**多项式**的系数
（`r²x = x³ + xy² + xz²`），而变换的基底是**按分量归一化**的直角高斯
`φ_i = N_i x^a y^b z^c e^{−αr²}`，`N_i ∝ 1/√∏_axis (2l_axis−1)!!`。所以单项式

```text
x^a y^b z^c ∝ √∏_axis (2l_axis−1)!! · φ_i
```

系数必须**逐分量乘 `√∏(2l−1)!!`**（f 壳层就是 1/√15 : 1/√3 : 1/√3）。漏了这一步，
"打掉 r²·p 成分"打掉的是另一个三维子空间，得到的七个函数混进了 `r²·p`。
`d_transform` 的系数是当初手推并按**归一化**基底校准过的，所以 d 一直是对的。

**为什么它能活这么久**：`TᵀST = I` 与"与 r²p 正交"两条判据都写错了同一套系数，
于是**实现与测试互相印证**。f 壳层在本项目的所有体系里都是**纯虚轨道**
（def2-TZVP 的水/O/F/C/N 都只用到一个 f 壳层，且能量上只以二阶量进入总能量），
所以症状只有 2.7e-6 Ha —— 一个会被"容差"吞掉的数字。如果哪天有人拿 f 去算
性质或相关能，这个错就会变成主项。

**修法与新的判据**：

- 代码：`f_transform` 里把两组系数按 `√∏(2l−1)!!` 换算成归一化基下的系数，
  顺手把 `(2l−1)!!` 提成模块级助手（`f_overlap_metric_value` 里原来有一份嵌套副本）。
- 测试：`f01_f_transform.rs` 的 r²p 向量改用换算后的系数；并新增一条
  **不依赖"哪三个向量"**的判据 —— 独立 Gram–Schmidt 出一组 l = 3 基 `Tₐ`，
  断言 `T Tᵀ = Tₐ Tₐᵀ`（差 < 1e-10）。两种基底之间只差一个正交阵，所以这条
  对"投影到哪个子空间"极敏感，恰好是上一版漏掉的。
- 端到端：H2O/def2-TZVP 的 HF 从 −76.0589636998 回到 **−76.0589663595**
  （PySCF −76.0589663585，差 1e-9），f 块的 `Tr(H1)` 从 −12.0953 回到 −11.55589。

**纪律**：验收判据里的每一组"构造性向量"都要问一句"它是在哪个基底下写的"。
"正交归一"是必要不充分条件 —— 任何 Gram–Schmidt 都给你正交归一，但不会告诉你
子空间对不对。

## 五十六、`BOHR_PER_ANGSTROM` 与 PySCF 的常数差 1.8e-8：一个真实的微小偏差（2026-10-27）

IN-01 拿 PySCF 当外部尺子时，`V = (P|Q)` 的特征值最好也只对到 **1.3e-7** 的相对差，
而积分本身在别的体系上是 1e-12 量级。查下去发现这个 1e-7 不是积分误差，而是**几何**：

| 常数 | 值（bohr/Å） | 出处 |
|---|---|---|
| K2 的 `BOHR_PER_ANGSTROM` | **1.889726089838572** | 我们的代码（注释写"CODATA 2018"） |
| CODATA 2018（$a_0 = 5.29177210903\times10^{-11}$ m） | **1.889726124625770** | 真值 |
| PySCF 的 `bohr`（$a_0 = 0.52917721092$ Å） | **1.889726124565062** | PySCF |

我们的常数折合 $a_0 = 0.529177220644$ Å，与 CODATA 2018 相对差 **1.84e-8** ——
注释里的"CODATA 2018 精确值"是不准确的。

**为什么一直没被发现**：它对**总能量**的影响在平衡构型上是二阶的。以 H2O/def2-TZVP 为例，
`dE/dR ≈ 0.01 Ha/bohr`，核间距相对变化 1.8e-8（绝对 ~4e-8 bohr）只带来 ~4e-10 Ha 的能量差
—— 比我们平时的判据（1e-6 Ha）小得多。但**核排斥能**是 1/R，1.8e-8 × 9.19 Ha = **1.7e-7 Ha**，
与实测的 `E_nuc` 差一模一样（`docs/status-v2.yaml` 里 def2-TZVP 水的那一轮就记过这个数）。

**这一轮没有改它**，原因是代价与风险不对称：`BOHR_PER_ANGSTROM` 在冻结的 K2 里，
改它会让所有"钉住的参考能量"在 1e-8–1e-6 Ha 量级上一起漂移（CuH/ECP、H2O/PBE、苯……），
而收益只是让比较 PySCF 的地板从 2e-8 降到 3e-11。所以先**记账并把判据写实**：
IN-01 的外部对照门限按 1e-7 写（而不是 1e-9），并在测试注释里指明这个地板来自几何常数。
下次动 K2 的 `CHANGELOG` 时（比如新增一个字段）顺手把它改成 CODATA 2018 的正确值，
并重钉受影响的参考值 —— 那一次改动本来就要 bump 版本。

**教训**：物理常数也要有出处与核对。这个值当初是"抄进来的"，而不是从 CODATA 的
$\hbar$/$e$/$m_e$/$\varepsilon_0$ 组合算出来的，所以错了 1.8e-8 也没人发现。
现在 `molecule.rs` 的单测只断言"`position_bohr()[0]` 等于这个常数"，**没有**断言它等于
CODATA 的值 —— 那是一条同义反复。正确的判据应该写成
`(BOHR_PER_ANGSTROM − 1e10/5.29177210903e-11).abs() < 1e-14` 这样的**外部锚**。

## 五十七、IN-01 的验收判据把"实现正确"与"辅助基完备"混在了一起（2026-10-27）

`project-phase2.md` §6.3 给 IN-01 写的判据是：

> `(ij|P)` 与直接 4 中心对比：拟合误差对 H2O/def2-SVP < 1e-6 Ha（能量）

实现落地后实测（我们的实现与 PySCF **逐位一致**，所以这不是"我方算错"）：

| 量 | 实测 | 由谁决定 |
|---|---|---|
| `E_J^RI − E_J`（精确 4 中心），`def2-SVP`+`def2-SVP-RI` | **6.14e-3 Ha** | 辅助基不完备（76 个函数） |
| RI-J 的 **SCF 总能量**与精确 SCF 的差 | 2.27e-3 Ha | 同上（有变分抵消） |
| 我方 `E_J^RI` 与 PySCF 同配对的差 | **1.37e-7 Ha** | 实现的数值误差（即 1.8e-8 的几何常数） |

`def2-SVP-RI` 是这一对的"官方伴随辅助基"，它把 46.845 Ha 的 Coulomb 能量拟合到
6.14e-3 Ha（相对 1.3e-4）。要求 <1e-6 Ha 等于要求辅助基把 Coulomb 能量拟合到
**2e-8 的相对精度** —— 那需要比 def2-QZVP-RI 还大一截的 fitting basis，不是 IN-01 的事。

**处置**：判据拆成两条（`qwb-scf/tests/in01_ri_fit.rs`）：

1. **实现正确性**（可执行、有外部尺子）：`|E_J^RI(我方) − E_J^RI(PySCF)| < 1e-6 Ha`
   —— 实测 1.4e-7，且三种辅助基给出**同一个**偏移（1.367/1.372/1.366e-7）。"同一个偏移"
   是关键旁证：如果偏移随辅助基变化，那才是积分错；恒定偏移就是几何常数。
2. **辅助基质量**（如实记账）：`E_J^RI − E_J = −6.14e-3 Ha` 写进测试打印与账本，
   断言只给一个宽松上界（2e-2），并配一个**对照组**（拿 STO-3G 当辅助基，误差 9.2e-1 Ha）。

**为什么要写"对照组"**：只断言 `|gap| < 2e-2` 的话，即使 `(ij|P)` 全部返回 0，
`E_J^RI` 也是 0、gap = −46.8 Ha 会超标（那还好）；但如果积分整体偏小 10%，
gap 可能仍在 2e-2 内。加一条"对照组必须差得多"+"与 PySCF 一致到 1e-6"，
才同时钉住"量级对"和"数值对"。

**为什么这类修正要单开一节**：判据写错和实现写错一样常见，但只有前者是"不许为了让
门禁变绿而降低要求"。这里的做法是**把判据换成更强的那个**（对照外部实现），
同时把原来想量的东西（辅助基质量）如实记下来 —— 而不是简单地把 1e-6 放宽成 1e-2。

## 五十八、SC-05 的墙钟判据：实测 0.15×，按 §2.5 记录降级（2026-10-28）

`project-phase2.md` §6.5 给 SC-05（RI-MP2）写的第三条判据是「墙钟优势 ≥ 3×（否则记录并
降级）」。实现落地后实测（苯/def2-SVP，`n_orb` = 114、`n_aux` = 372，release 构建，
只量 MP2 部分）：

| 路径 | 墙钟 | 相关能 |
|---|---|---|
| canonical（4 指标四步半变换） | **7.14 s** | −0.79790039 |
| RI（3 中心组装 + 白化 + 收缩） | **48.32 s** | −0.79743038 |

比值 **0.15×** —— RI 慢 6.8 倍。两条路径的能量都与 PySCF 对到 1e-9，所以这不是实现
错误，是**代价结构**不同：

* canonical 版是我们已经优化过的形态：`n_occ · n⁴` 的四步半变换，水/def2-SVP 只要
  1.7e6 次乘加，苯上 7 s。它天然省掉了"建 3 中心张量"这一大块。
* RI 版的 3 中心张量是**逐壳层三元组**现场用 `primitive_component` 算的：苯上大约
  130 个辅助壳 × 2211 个轨道壳对，每个块还要过球谐变换。3 中心这一步就占了大头。
* RI 的经典优势来自**内存**（`n_aux·n²` 而不是 `n⁴`）与**渐近阶**（O(N⁴) vs O(N⁵)），
  而这两个优势要在"大体系 + 壳层块屏蔽 + 直接积分"的实现里才兑现。本项目的 3 中心
  路径还是"老实算"的版本。

**处置（按 §2.5 而不是改判据）**：SC-05 的另外两条（与 canonical 差 0.085 mHa、`ri_error`
落盘）都达标，所以 SC-05 记 done；墙钟这一条**如实记下调级**，并在 USAGE §3.7 与账本里
写明"RI-MP2 可用但不宣称更快"。升级路径留给 IN-04（RI-J 的 Fock 路径，会用同一套
3 中心积分）与 IN-05（并行）—— 那两项的判据本身就带"否则记录并降级"，改动会同时
受益。

**附带的一条设计取舍**：引擎的 `kind: ri-mp2` **同时**算 canonical 来填
`ri_error_hartree`。这让"近似必须留痕"（K10 第 ③ 条）在数据上成立，代价是作业更慢。
K9 的 `ri_error_hartree` 字段没有别的填法 —— 辅助基的拟合误差只能通过与精确值比来量，
或者与更大的辅助基比（我们没有更大的，`def2-tzvp-ri` 带 g 函数，球谐变换还没做）。
所以判据 2 量的是**内核**（两条路径各自的 MP2 内核），而不是整个作业的墙钟；
两个数都打印在测试输出里，谁都可以复核。

## 五十九、同一个「偏移 vs 绝对列号」的坑，一轮里踩了两次（2026-10-28）

RS-01（CPHF / 静态极化率）卡了一轮，第 19 轮结束时账本上记的是「三处给出三个互相
矛盾的数（37.96 / 80.55 / 30.34），说明某个系数或映射错了」。第 20 轮定位到根因：
**两处都把虚轨道的偏移（`0..n_vir`）当成了系数矩阵的绝对列号**。

| 位置 | 错 | 对 |
|---|---|---|
| `qwb-response/src/mo_integrals.rs`（5 处） | `c(mu, a)` | `c(mu, n_occupied + a)` |
| `qwb-response/tests/rs01_hessian_operator.rs` | `rotated_density(.., i, a, ..)` | `rotated_density(.., i, n_occupied + a, ..)` |

症状各不相同，所以一开始没认出来是同一个错：

* `mo_integrals.rs` 那一处让 AO→MO 的两块 2e 积分收缩到了错误的列上 ——
  Rust 给 `T1 = T2 = T3 = 4.7445`（三者还恰好相等，很有迷惑性），numpy 给
  `0.0313 / 0.8034 / 0.0313`；
* 测试那一处旋转的是 `i` 朝一个**占据**列，于是同一条路径的有限差分给出 37.96，
  而独立 numpy 实现给 80.55。

修好后：Rust 与 numpy 两个独立实现在水/STO-3G 的 10 个对上一致到 **2e-5**
（中心差分步长误差），比值 `d²E/dλ² / (A+B)_pp` 全是 **4.000000**；极化率与有限场
一致到 **1e-7**（判据 1e-4）。

**为什么值得单开一节**：这个错不属于"公式推错"，而属于**命名**。当同一个物理量
同时有两种下标（"第几个虚轨道" vs "第几列 MO"）时，`a`、`b` 这种短名字不会提醒
任何人。所以修的时候顺手把 `mo_integrals.rs` 里的变量改成了 `column_a` / `column_b`：
名字本身就能挡住下一次同样的错。

**附带一条方法论**：上一轮我记的是"三处矛盾"，其实三处里只有两处是错的 ——
`(A+B)` 算子本身一直是对的（numpy 用它算出的 4·(A+B)_pp 与能量二阶导一致）。
把"哪些数互相矛盾"降级成"哪两个实现不一致"，再用一个**第三方实现**（numpy，
完全不共享代码）当裁判，是这一轮能收敛的关键；只盯着 Rust 侧自洽是解不开的。

## 六十、VF-01 的判据把「与库的差」写成了对实验值的 0.2–0.5 eV（2026-10-28）

M4 的能力侧（RS-02 TDA/TDDFT、RS-03 CIS）在第 21–25 轮全部交付：H2O（STO-3G 与

方法精度，数据轨无法交付。建议把判据改成两条可执行的：①「CSV 带来源」保留
（指生成脚本 + PySCF 版本，**不是**我没有核对过的 DOI —— 这一轮没有伪造任何文献
DOI，宁可把来源写成脚本名）；②「与库的差在容差内」拆成「与同方法同基组参考差
< 1e-3 eV」（实现正确性）+「与实验值的偏差如实记录并按方法层级归档」（方法精度）。
再补上丙酮，VF-01 就是纯数据活。

**教训（与 IN-01 的 f-sum、SC-05 的墙钟同源）**：验收判据里凡是出现"与 X 差 < 容差"，
都要问一句 **X 是谁** —— 外部参考实现？实验？还是自己的另一条路径？三者的容差量级
完全不同（1e-7 / 1e0 / 1e-3），混在一起写会得到一条谁都过不了、或者谁都能"过"的判据。
这一轮选择的处置是**记 blocked + 写清两种读法各自的实测值**，而不是挑一个宽松的
容差把它"过"掉。

## 六十一、COSMO 的对角元：`1.07·2√(πA)` 不是 `1.07√(4π/A)`（2026-10-29）

SV-01 第二半（COSMO 表面电荷）写的第一版把对角元写成 `1.07·√(4π/A_K)`。这条式子
在**密度**形式（未知量 `σ`，方程 `Σ A_K' σ_K' /d = −V`）里看起来像文献里的写法，
但乘上面积换成电荷形式后差了一个 `A_K` 因子 —— 于是球壳的行和变成
`4πR + O(√M)`（随碎片数**发散**），实测 `R = 2 Å`、`M = 2000` 时行和高 24.2%，
Born 能比解析值高 24%。诊断方式很直接：算「均匀电荷球壳」的行和，和解析的 `4πR`
比 —— 一个自洽的离散化必须让行和收敛到 `4πR`。

正确写法：把碎片近似成半径 `a = √(A/π)` 的圆盘，圆盘上的自积分是

    ∫_disc dA'/|r − r'| = 2πa = 2√(π A_K)

再乘 Klamt–Schüürmann 1993 的经验因子 `1.07`（圆盘近似偏小，补 7%），即
`S_KK = 1.07·2√(π A_K)`。此时行和 = `4πR + 0.28√(πA)`，是 `O(1/√M)` 的收敛余项。

**第二个坑：Coulomb 核矩阵不定。** `1/d_ij` 不是正定矩阵（有负本征值），加上对角
自作用项后 Cholesky 仍可能失败 —— `R = 1.5 Å`、`M = 400` 的球就报「not positive
definite」（更大的球以前"碰巧"能过）。所以 `cosmo.rs` 用自带的部分选主元高斯消元
（`solve_dense`），不用 `qwb_linalg::solve_symmetric`。

**实测（裸点电荷 + 球形空腔，判据 = 解析 Born `−½(1−1/ε)q²/R`，ε = 78.355）**：

| `M` | ΔG (Hartree) | 相对误差 | 诱导电荷误差 |
| --- | --- | --- | --- |
| 125 | −0.1256738421 | 3.78% | 3.78% |
| 250 | −0.1333949725 | 2.14% | 2.14% |
| 500 | −0.1349219585 | 3.31% | 3.31% |
| 2000（诊断用） | −0.135332（ε→∞ 极限） | — | 2.30% |

残差 4e-16（线性方程解对了），误差全部来自 `1.07` 圆盘近场近似；误差不单调、量级
2–4%，所以测试里**不**声称「随 M 单调下降」，只钉住 5% 的实测上界（`docs/status-v2.yaml`
里如实写）。这是裸点电荷的最坏情形（能量全来自近场）；真机分子有电子云分摊，
误差更小，但本文档不据此放宽 SV-01 的主判据。
