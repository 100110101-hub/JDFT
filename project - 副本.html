2. 目标与非目标

2.1 目标

从零实现一个分子 DFT 软件：

  • 引擎自研：不调用 PySCF/ORCA/Gaussian/QE/Psi4/libxc/ase 等电子结构引擎或泛函库。
  • 数据是中心：基组、ECP、泛函、网格、溶剂参数的获取、本地实现、验证、版本化是核心工作。
  • 工作流完整：项目 / 分子 / 任务 / 结果 / 调度 / 复现。
  • 界面完整：GUI（Python + PySide6）+ Python API（pyo3）+ CLI（clap），共用同一套 Task 模型。
  • 可复现是底线：每个结果都能回溯到输入 + 数据快照 + 环境（env.json 必须含 Rust toolchain、Cargo.lock 的 sha256、crate 版本清单）。

2.2 与 Jaguar 的对齐范围（v2.1 新增：回答"模仿到什么程度"）

第一阶段对齐 Jaguar 的产品面与方法集合，不复制它的算法内核。

为什么不模仿 PS 积分：Jaguar 的 pseudospectral 方法把 Coulomb/exchange 放到网格上算， 是另一套积分与误差分析体系。本项目契约要求"每个数都能回溯 + 与解析/文献对照"， 而 PS 的误差来源（网格密度、去别名）会把 T1 首次端到端推远，并把 §9 的三层验证搅浑。 所以：解析积分（Obara-Saika）+ 网格只用于 XC，与 §6 的 I/X 轨一致。

3. 组织原则

  1. 契约先行，并行不返工。K1–K6 已冻结（C 轨完成），数据/引擎/产品三轨可以并行。
  2. 数据层随垂直切片增量补。第一次只需要 H 与 STO-3G。
  3. 引擎按垂直切片推进，不做层内串行。第一次就跑通一条能量，把集成风险前移。
  4. 产品轨先于引擎成熟开工。Product 轨前期用 mock 数据。
  5. 每个工作包都可独立验收。没有"感觉差不多了"这一步；§6 每行都有可复制命令。
  6. agent 不自由发挥；但也不允许被模糊处卡死 —— 见 §10.3 的决策规则。
  7. Rust 特有约束：
    • #![deny(unsafe_code)] 默认；只允许 3 类 crate 例外：FFI（BLAS）、SIMD intrinsics （wide 已封装）、获批的热点优化。例外需 // SAFETY: 注释 + 人类批准 + 进 scripts/unsafe_allowlist.txt。
    • Cargo.lock 入 git，禁止无 PR 记录 cargo update。
    • cargo fmt --check / cargo clippy -- -D warnings 必须全绿才能合入。
    • workspace 层级不得引入循环依赖。
    • 三方依赖只能出现在 qwb-core/Cargo.toml 的 [workspace.dependencies] （scripts/check_deps_centralized.sh 强制）。

风险优先级：集成风险 > 数学正确性风险 > 数据正确性风险 > 性能。

K1 · 数据 Schema

路径：qwb-contracts/schema/（生成物）、qwb-core/crates/qwb-registry/src/*.rs（真相源）

生成方式（已定案）：schemars 从 Rust 类型生成，BasisSet 等类型即唯一真相源。 生成器：cargo run -p qwb-registry --bin qwb-gen-schemas -- <dir> [--check]。 每类产出 <kind>.schema.json（工具读）+ <kind>.schema.yaml（人读，K1 规定文件名）。

7 类：basis、ecp、functional、grid、solvent、molecule、registry （枚举 qwb_registry::verify::DataKind，顺序即生成顺序）。

共同字段（在 5 个数据集类型里内联声明；schema.rs 的测试强制 5 处定义逐字节一致）：

字段 类型 说明
name String 数据键名（数据目录下的标识）
version String 独立 semver；变更即 bump
citation Vec<Citation> required，≥1 条；每条 title + doi/url
license License required；spdx、commercial_ok、redistribute_ok
created String ISO 8601 UTC
sha256 Option<String> 工具生成（规则见下）
notes Option<String> 备注/来源说明

规范化 sha256 规则（唯一实现 qwb_registry::sha256）：解析 YAML → 删顶层 sha256 → 转 JSON（键字典序）→ 对紧凑 JSON 取 SHA-256（64 位小写 hex）。 与排版/注释/键序无关，改一个数字必换摘要。qwb-stamp-data 打戳（会丢 YAML 注释， 所以说明写进 notes）。

各类型特有字段（与代码一致）：

  • BasisSet：elements: Vec<String>、angular: spherical|cartesian、 normalization: l2|none、role: orbital|ri-j|ri-jk|ecp-fit、 shells: Vec<ShellBlock>（ShellBlock { element, shells: Vec<Shell> }， 每元素一块，必须与 elements 一一对应）。 原因：一个基组文件可覆盖多元素（D-03 的 STO-3G 覆盖 H/C/N/O/F），平坦 shells[] 无法区分元素。
  • Shell：l: u32、exponents: Vec<f64>（Bohr⁻²，大→小）、 coefficients: Vec<Vec<f64>>（每条内层 = 一个收缩函数，长度 == exponents.len()）、 contraction_type: segmented|general。 原因：def2-TZVP 的通用收缩（D-05）无法用一维系数表达。
  • Ecp：element、n_core_electrons、z_eff（必须 == Z − n_core）、 r_power_convention: "r^n"|"r^(n-2)"、local_part{id,terms[{power,exponent,coefficient}]}、 nonlocal_parts[{l,id,terms[]}]。
  • Functional：components[{id,weight}]、requires{rho,sigma,laplacian}、 parameters: BTreeMap<String,f64>、stability{density_floor,sigma_ceiling}。
  • GridLevelDef：level: coarse|normal|fine|veryfine、radial_points、lebedev_order、 becke_sharpness、radii_scale?、cutoff（Bohr）。
  • Solvent：epsilon、temperature_K、atomic_radii: BTreeMap<符号,f64>（Å）、 cavity_model: none|pcm|smd、scale。
  • MoleculeFile（用户输入，不受 G2 许可门禁）：name、notes?、 atoms[{symbol,position_angstrom}]、charge、multiplicity、citation?、 created、sha256?。校验含电子数奇偶与多重度一致、坐标重合检测。
  • RegistryManifest：schema_version（必须 == K1_VERSION）、name、version、 created、features: Vec<String>、 5 个条目表 bases/ecps/functionals/grids/solvents，每条 {name, path, sha256}。

校验代码（机器可读）：yaml.parse、schema.deserialize、sha256.compute、 sha256.mismatch、g2.citation、g2.license、g2.sha256、semantic、registry.*。 verify 与 load 的语义分工见 §8.6。

Rust 实现约定：所有类型 #[serde(deny_unknown_fields)] + #[non_exhaustive]； 反序列化拼错字段必须报错。

冻结约定：

  • 公共 struct/enum 一律 #[non_exhaustive]；因为 non_exhaustive 禁止跨 crate 的 struct literal，所有类型都提供 new(..) 与 with_* 建造方法（API 的一部分，不是可选项）。
  • 公共字段后缀 _hartree/_bohr/_debye/_angstrom，禁止裸 energy。
  • 错误 enum 只允许新增变体（#[non_exhaustive]），禁止删除；新变体必须进 exit_code()。
  • 所有跨线程类型 Send + Sync（有静态断言测试）。
  • Engine::run 接受 &dyn Reporter，引擎不得直接写 stdout。
  • Registry 在契约 crate 里只是"数据根 + 本次计算声明的 feature 集合"的句柄， 不解析数据文件（加载属 D-01）。Engine::new/with_backend 校验： 数据根不存在 → Data；声明了 SUPPORTED_FEATURES 之外的 feature → Unsupported。
  • 矩阵 JSON 表示 = list-of-list（K4 二选一定案）；由 engine-api 显式 serde 适配， 不依赖 nalgebra 私有布局；None 字段省略而非写 null。
  • SUPPORTED_FEATURES（第一阶段词汇表）： jobtype:sp|opt|freq、basis:orbital|ri-j|ri-jk|ecp-fit、 functional:lda|gga|hybrid、grid、solvent:vacuum|implicit、ecp。 表外 feature（如 functional:meta-gga、solvent:smd）→ Unsupported。 "声明支持 ≠ 本构建实现"：后端还会再判一次。

8. 数据层详细要求（项目中心）

8.1 基组

来源：BSE 导出 + 一手文献核对。每个基组追溯原始 DOI，并核对 H、C、N、O 至少 3 个元素 的指数/系数。不得从其他项目代码仓库复制文件（BSE 网站导出可以）。

本地实现：

  • 内部统一 schema（YAML → serde_yaml → BasisSet）。
  • 加载器：qwb-registry → Registry → get_basis(name) -> BasisSet。
  • 枚举/球谐切换只有一处：BasisSet.angular；Engine 显式读取，禁止隐式默认（R-06）。
  • 归一化只有一处：加载时一次性处理，运行时不转换。
  • 多元素文件用 ShellBlock（§4 K1），每个元素必须恰好一个块。

验证（CI）：

  1. schema 校验（deny_unknown_fields）。
  2. 指数/系数与 BSE 逐项 diff（< 1e-12 相对）。
  3. 归一化：H2/STO-3G 重叠积分与解析闭式一致（I-02）。
  4. 球谐 vs 笛卡尔：d 壳层函数数 5 vs 6（计数断言），能量差异存在且有限。
  5. ECP-pairing：有 ECP 元素必须能找到匹配基组，否则 Registry::load_pair 返回 EngineError::Data。

8.2 ECP

  • 来源：Stuttgart / def2-ECP 官方 + BSE 导出（再分发条款必须先确认，见 §14 #20）。
  • 陷阱显式声明：r^n vs r^(n-2) 强制 r_power_convention，加载器统一转内部约定。
  • 配对校验：Registry::load_pair(basis, ecp) 是唯一入口。

9. 验证体系

三层，缺一不可：

  1. 单元层：每 WP 自带（积分对照、泛函导数、网格精度、ECP 矩阵元、状态机转移）。
  2. 物理极限层：氢原子解析解（V-01）、均匀电子气、HF 一致性（V-02）、网格 Σw 收敛。

本地/CI 门禁（一条命令）：Windows 用 scripts/verify.ps1，Linux/CI/WSL 用 scripts/verify.sh（两者覆盖同一清单，见 §13）。它等价于：

  • cargo test --workspace（含 proptest）

门禁 G：

  • G1 契约门禁：K1–K6 已冻结；改动只允许新增；破坏性改动需人类评审。
  • G2 数据门禁：D 轨每次合入必须有 citation + license + sha256；cargo-deny 许可映射一致。

10. Agent 执行协议

10.1 开工前（每个 WP）

  1. 读 docs/status.yaml，确认该 WP 依赖全部 done。
  2. 读 qwb-contracts/ 中相关 K 文件与 qwb-contracts/studio/*.md。
  3. 检查产物是否已存在；若存在且验收通过，标 done 不重复做。

10.2 执行中

  1. 只改本 WP 涉及的代码/数据。
  2. 不得改 K1–K6 的语义（见 §10.4）。
  3. 不得删除或修改其他 WP 的产物。
  4. 每次提交附件：cargo fmt --check + cargo clippy -- -D warnings + 该 WP 验收命令输出摘要。
  5. 公共 API 变更（pub 项）必须在 PR body 里显式列出，触发 G1 复核。
